# 세 세션 합의 규칙 — quiz-validate 생성 프롬프트

- 작성: 260811-6 검토팀 (조정자)
- 이 폴더(`consensus/`)의 기준 문서다. **세 세션은 움직이기 전에 이 문서를 읽는다**

## 0. 무엇을 정하는가

**quiz-validate 커스텀 명령어를 만들어 내는 생성 프롬프트를 백지에서 다시 정한다.**

- 산출물은 `consensus/r3-agreement.md` 한 편이고, 그 안에 최종 생성 프롬프트가 들어간다
- **지금의 `.claude/commands/quiz-validate.md`를 고치는 작업이 아니다.** 현행본은 참고 자료일 뿐이며, 백지에서 다시 쓴다
- 명령어 파일 본문이 아니라 **그 파일을 만들어 내는 프롬프트**가 대상이다. 둘은 다르다

## 1. 참가 세션

세션은 **이름이 아니라 주 작업 폴더로 식별한다.** 이름은 보는 쪽마다 다르게 보이고 바뀌지만 폴더는 안 바뀐다.

| 부를 이름 | 주 작업 폴더 | 이 협의에서 맡는 것 |
|---|---|---|
| 260811-5 구현팀 | `…/DS26/260812 바이브코딩 교육` | 프롬프트 제출, 논의 |
| 260811-6 검토팀 | `…/Downloads/PRD 검토` | 프롬프트 제출, **조정** |
| 260811-7 구현팀 | `…/vibe coding (taehojo)/5장 퀴즈게임 by ClaudeDesktop` | 프롬프트 제출, **실행**, **최종 결정** |

## 2. 역할

### 조정 — 260811-6 검토팀

- 갈린 지점을 집계하고 합의문을 쓴다
- **1라운드에는 다른 둘과 똑같이 프롬프트를 제출한다.** 서로 안 보고 쓰는 구간이라 조정자라고 유리할 것이 없다
- **2라운드부터는 새 의견을 내지 않는다.** 자기 1라운드 안을 변호하지 않고 집계만 한다. 자기 안을 자기가 심사하지 않기 위해서다

### 실행 — 260811-7 구현팀

- 세 프롬프트를 각각 돌려 명령어 파일을 만들고, 그 명령어를 실제로 실행한다
- **셋 중 유일하게 `/quiz-validate`를 실행할 수 있는 세션이다.** 슬래시 명령어는 주 작업 폴더의 `.claude/commands/`만 읽는데, 나머지 둘은 주 폴더가 저장소 밖이다
- **생성된 명령어 파일과 실행 출력을 요약하지 말고 원문 그대로 올린다.** 요약하는 순간 판정이 섞인다
- 자기 프롬프트도 자기가 돌린다. 원문 그대로 올리는 조건이 그 편향을 막는 장치다

### 최종 결정 — 260811-7 구현팀

- 3라운드에서 합의가 안 되면 자른다
- 파일을 소유하고 실행할 수 있는 쪽이 정한다

## 3. 라운드

### 1라운드 — 격리

- 세 세션이 **서로 안 보고** 각자 생성 프롬프트를 한 편씩 쓴다
- **이 구간에는 세션 간 메시지를 보내지 않는다.** 조정자의 진행 신호만 예외다
- 남의 `r1-*.md`를 미리 열지 않는다. 먼저 올린 쪽 문장에 나머지가 끌려가면 독립성이 사라진다
- 다 올라온 뒤에 조정자가 공개 신호를 보낸다

### 2라운드 — 공개

- 각자 다른 둘을 읽는다
- 260811-7이 세 프롬프트를 돌린 실행 결과를 `r2-run.md`에 원문으로 올린다
- 조정자가 **갈린 지점 목록**을 `r2-diff.md`에 만든다
- 각 세션은 갈린 지점에만 답한다. **동의하는 부분은 다시 쓰지 않는다.** 안 그러면 문서가 세 배로 불어난다

### 3라운드 — 수렴

- 갈린 지점마다 결론을 낸다
- **합의가 안 되면 소수 의견을 그대로 병기한다.** 억지로 하나로 만들지 않는다
- 조정자가 `r3-agreement.md`를 쓰고, 260811-7이 확정한다

### 종료 조건

**3라운드 고정.** 또는 갈린 지점이 0이 되면 그 자리에서 닫는다.

## 4. 판정 기준

**프롬프트만 읽고 판정하지 않는다.** 돌려서 나온 명령어로 판정한다.

| # | 볼 것 | 왜 |
|---|---|---|
| 1 | **지시가 실제로 실행되는가** | 현행본의 "Node로 `validateData()`를 그대로 돌려라"가 실행되지 않는다. `script.js`에 `export`가 없고 마지막 줄이 `document.addEventListener(...)`라 읽는 순간 `ReferenceError`가 난다 |
| 2 | **새 검증 기준을 만들지 않는가** | 기준은 `spec/PRD.md`와 `spec/IMPL-PLAN.md`에 이미 있다. 명령어가 기준을 새로 지어내면 규격이 둘이 된다 |
| 3 | **규격의 절 번호를 정확히 가리키는가** | PRD 3.6절 끝의 "위 세 규칙"이 무엇인지, 2.1절 규칙이 거기 드는지가 현행본에서 어긋나 있다 |

세 항목은 **오늘 현행본을 검토하다 실제로 걸린 자리**에서 나왔다. 근거는 `history/33-question-source-verification.md`가 아니라 이 폴더 밖의 검토 기록에 있으며, 1라운드에서는 이 표만 보고 쓰면 된다.

- **`history/`의 번호 체계와 섞지 않는다.** 저기는 번호순이 시간순이고 여기는 라운드순이다. 한 폴더에 두 체계를 두면 다음 세션이 어느 규칙인지 매번 판단하게 된다
- 각 세션은 **자기 문서만 올린다.** 남의 문서를 고치지 않는다

## 6. 소통 규칙

- **내용은 저장소, 신호만 `SendMessage`.** 메시지에는 판단을 한 줄도 담지 않는다. "`consensus/r1-impl7.md` 올렸다"까지만
- 판단이 메시지에만 남으면 **학생이 재현할 수 없다.** 이 실습의 산출물은 과정 자체다
- **보내기 전에 `ListAgents`를 먼저 돌린다.** 맨 이름으로는 배달되지 않고 `[ref]`를 붙여야 하는데, `[ref]`는 목록을 읽은 직후에만 유효하다
- 회신은 받은 메시지의 `from` 값을 그대로 `to`에 넣는다
- 자기 세션 제목은 세션 안에서 못 읽는다. 받은 메시지의 `from-name`에 보내는 쪽 제목이 실려 온다
