# Study03_QuizGame

브라우저에서 바로 즐기는 상식 퀴즈 게임이다. 이름을 입력하고 카테고리를 골라 4지선다 문제를 풀면, 답을 고르는 즉시 정답 여부와 해설이 나온다. 한 판이 끝나면 점수가 순위표에 남는다.

계정도 서버도 빌드 도구도 없다. GitHub Pages에 정적 파일 네 개를 그대로 올리고, 순위 기록은 브라우저의 localStorage에 남는다.

## 현재 상태

**여섯 단계 중 4단계까지 구현했다.** 한 판 10문제를 끝까지 풀면 결과 화면에 점수와 정답률, 순위 진입 여부가 나오고 기록이 순위표에 남는다.

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 데이터 검사 함수와 `questions.js` | 완료. 검토 의견 반영 완료 |
| 2 | `index.html` 골격과 시작 화면 | 완료 |
| 3 | 문제 선정, 퀴즈 진행, 즉시 피드백 | 완료 |
| 4 | 결과 화면과 순위 기록, 순위표 화면 | 완료. 검토 요청 |
| 5 | 반응형 마무리와 에러 처리 | |
| 6 | 배포와 배포 후 확인 | |


### 개정 전 판본

PRD는 세 차례 개정을 거쳤다. 검토 전후를 대조할 수 있도록 남겨 두었다.

| 문서 | 내용 |
|---|---|
| [PRD-v3](archive/PRD-v3.md) | 2차 검토 반영본 |
| [PRD-v2](archive/PRD-v2.md) | 1차 검토 반영본 |
| [PRD-v1](archive/PRD-v1.md) | 최초 작성본 |

3차 개정은 구현 계획을 쓰다 발견한 것에서 나왔다. `beforeunload` 핸들러를 해제하는 시점 셋 중 하나가 도달할 수 없는 경로였다. 등록은 판을 시작할 때 하고 데이터 검사는 페이지가 뜰 때 도는데, 검사가 실패하면 판 자체가 시작되지 않으므로 해제할 핸들러가 없다.

`README-v1` ~ `README-v3`도 같은 폴더에 있다. 각 PRD 시점의 저장소 상태를 담은 스냅숏이다.

## 구현 계획

[구현 계획](spec/IMPL-PLAN.md)은 PRD 6절의 여섯 단계를 그대로 골격으로 쓰고, 무거운 단계만 하위 작업으로 쪼갰다. 단계마다 만들 파일, 정의할 함수와 그 책임, 선행 조건, 그리고 **무엇을 눌러 무엇을 확인하는지**까지 적었다.

빌드 도구도 테스트 프레임워크도 쓰지 않으므로 검증 수단은 둘뿐이다. 페이지 로드 시점에 도는 데이터 검사 함수, 그리고 브라우저에서 직접 밟는 수동 체크리스트다.

계획에는 위험 구간 여섯 개를 따로 표시했다. **화면상으로는 정상으로 보이면서 결과만 틀리거나, 배포해야만 드러나는** 종류다.

| 위험 | 증상 |
|---|---|
| 전 범위 도전에서 합친 결과를 다시 섞지 않음 | 카테고리 순서대로 출제된다 |
| 선택지를 섞은 뒤 `answer`를 갱신하지 않음 | 채점만 조용히 틀린다 |
| 저장 함수가 인덱스를 이름과 점수로 찾음 | 동명이인의 기록과 구별되지 않는다 |
| 날짜에 `toISOString()`을 씀 | 오전 9시 이전에 전날 날짜가 찍힌다 |
| 피드백 영역에 `aria-live`를 줌 | 스크린리더 낭독이 도중에 끊긴다 |
| 자원 참조에 절대 경로를 씀 | 배포하면 404가 난다 |

## 기능

- 4지선다 객관식. 카테고리는 한국사, 과학, 지리, 예술과 문화 네 가지
- **어느 모드든 한 판은 10문제, 만점은 10점**
  - 카테고리별 도전: 고른 카테고리에서 10문제를 뽑는다
  - 전 범위 도전: 두 카테고리에서 3문제씩, 나머지 둘에서 2문제씩 뽑는다. 어느 쪽이 3문제인지는 판마다 달라진다
- 판마다 문제와 선택지를 새로 뽑고 새로 섞는다
- 답을 고르는 즉시 정답, 오답 표시와 해설
- 문제마다 난이도 배지 (초급, 중급, 고급)
- 최종 점수와 정답률
- 순위표 다섯 개 (카테고리별 상위 5명씩, 전 범위 상위 10명)
- 다시 열어도 남아 있는 순위 기록

만점을 두 모드 모두 10점으로 맞춘 덕에, 나중에 문제를 늘려도 순위표 구조와 지난 기록이 그대로 남는다.

자세한 요구사항과 단계별 완료 기준은 [PRD](spec/PRD.md)에 있다.

## 기술 스택

- HTML, CSS, 순수 자바스크립트
- 라이브러리와 프레임워크 없음
- 파일 구성: `index.html`, `style.css`, `script.js`, `questions.js`

문제 데이터를 JSON이 아닌 `questions.js`에 두는 데는 이유가 있다. `<script>` 태그 순서만으로 로드 순서가 정해지고 초기화가 동기적으로 끝나므로, 데이터 검사를 페이지가 뜨는 시점에 한 번에 마칠 수 있다. `fetch()`로 바꾸면 초기화가 비동기가 되어 로드 실패 처리와 검사 시점이 복잡해진다.

## 실행 방법

구현이 끝나면 배포 URL로 접속하면 된다. 설치할 것도, 띄울 서버도 없다. 로컬에서 확인할 때는 `index.html`을 브라우저로 열어도 된다.

## 배경

『바이브 코딩』 5장 실습으로 만드는 앱이다. 클로드에게 PRD를 쓰게 하고, 그 PRD를 새 세션에서 검토시켜 고친 뒤, 구현까지 진행하는 과정을 담는다.
