강의 노트를 다룬다. 세 가지를 한다.

| 인수 | 하는 일 |
|---|---|
| `write` | 새 노트나 목을 쓴다 |
| `check` | 이미 있는 노트를 검사만 한다. 고치지 않는다 |
| `fix` | 검사하고 고친다. 고친 목록을 낸다 |

인수가 없으면 `check`로 본다.

## 1. 먼저 매체를 가른다

**매체마다 문체가 다르다. 섞으면 안 된다.**

| 매체 | 무엇으로 아나 | 문체 |
|---|---|---|
| 노션 | 페이지 id를 받았거나 `<details>`가 있다 | 음슴체 |
| 콜랩 | `.ipynb`이다 | 서술체 |
| 저장소 문서 | `.md`이고 `spec/`이나 `history/`에 있다 | 그 문서의 문체를 따른다 |

매체를 가르지 못하면 묻는다. 추측하지 않는다.

## 2. 공통 규칙

**두 매체에 모두 적용한다.**

| 무엇 | 규칙 |
|---|---|
| 긴 줄 | 본문에 `—`를 쓰지 않는다. 쌍점을 쓴다 |
| 제목 구분자 | 제목에 `—`나 쌍점을 쓰지 않는다. 어순을 바꿔 명사구 하나로 만든다 |
| 셈 | 단위를 밝힌다. 「넷」이 아니라 「4종」, 「3건」, 「다섯 줄」 |
| 구현 단계 | 「N단계」로 줄이지 않는다. 「구현 N단계」로 쓰고, 1차와 2차가 섞이면 차수를 밝힌다 |
| 한 동작 한 낱말 | 「보며 확인함」처럼 한 동작을 두 낱말로 부르지 않는다 |
| 가운뎃점 | 열거에 `·`를 쓰지 않는다. 쉼표를 쓴다 |
| 절 참조 | 절 번호 앞에 문서 이름을 붙인다. 「4.2절」이 아니라 「PRD 4.2절」 |
| 층위 | `##`은 장, `###`은 절이다. 과거 기록을 가리킬 때는 그 문서가 쓴 낱말을 그대로 쓴다 |

**제목 어순을 바꾸는 법은 셋이다.**

| 뒤엣것이 무엇인가 | 어떻게 |
|---|---|
| 한정어 | 앞으로 보낸다. 「깃허브 가입 — 구글 계정으로」 → 「구글 계정으로 깃허브 가입」 |
| 열거 | 세는 말로 묶는다. 「계정 만들기 — 구글, 깃허브, Supabase, Vercel」 → 「4종 서비스에 계정 만들기」 |
| 조건 | 「~ 시」로 줄여 앞에 둔다. 「실패했다고 알려 오면 — 맥에서 직접 설치」 → 「설치 실패 시 맥에서 직접 설치」 |

## 3. 노션 노트의 규칙

**문체는 음슴체이고 어휘는 문어체다.** `~/.claude/STYLE.md`가 정본이다.

- 서술형 종결(`~한다`, `~나온다`)을 쓰지 않는다
- 굵게 표기를 쓰지 않는다. 강조가 꼭 필요하면 `<span underline="true">`를 절제해 쓴다
- 강조 부사를 쓰지 않는다
- 세 줄 넘는 산문 문단을 만들지 않는다. 비교는 표로 낸다
- 개조식으로 쓰고 마침표를 붙이지 않는다

**구조는 토글이다.**

```
<details>
<summary>제목</summary>
	- 항목
</details>
```

- 들여쓰기는 탭이다. 공백이 아니다
- 계층은 `5.3.N.M`이 탭 2개, `a)`가 3개, 그 아래가 4개, 항목이 5개다
- 사람이 할 것은 제목에 `(사용자 작업)`을 붙인다
- 클로드에게 시킬 것은 프롬프트를 인용문(`> `)으로 적는다

**독자는 대학 신입생이다.** 기술 용어는 처음 나올 때 한 줄로 풀어 준다.

```
- 와일드카드(wildcard): 바뀌는 자리를 `*`로 두어 여러 주소를 한 줄로 적는 표기
```

**실습의 범위를 좁게 잡지 않는다.** 학생이 직접 하지 않더라도 프롬프트에 들어가거나 클로드의 작업 결과에서 확인되는 것은 실습이다. 그 자리에서 무엇을 확인하는지 짚는다.

**깃허브 링크를 달아 준다.** 규격, 문서, 코드를 가리킬 때 주소를 함께 적는다. 시점을 고정해야 하는 자리는 태그로 걸고, 최신을 따라가야 하는 자리는 `main`으로 건다.

## 4. 콜랩 노트의 규칙

**문체는 서술체다.** 노션과 반대다.

- 종결은 `~한다`, `~이다`로 한다
- 목 끝에 다음 목으로 잇는 한 줄을 둔다. 「이제 단락 평가에 대해 공부하자.」
- 목이 끝나면 `<div style="page-break-after: always;"></div>`를 둔다
- 줄을 나눌 때는 줄 끝에 공백 두 칸을 둔다
- 예약어와 자료형은 백틱으로 감싼다
- 굵게 표기는 거의 쓰지 않는다

**노트 첫머리에 학습 목표를 둔다.**

```
<h1>학습 목표<span class="tocSkip"></span></h1>
```

- 「~할 수 있다」로 끝나는 항목을 열 개 안팎 나열한다
- 목 번호는 `## 1. 조건 처리 구조`, `### 1.1 단일 행 if/else` 꼴이다

**마크다운 셀과 코드 셀을 번갈아 둔다.** 설명을 먼저 내고 코드를 뒤에 둔다. 코드에는 주석으로 무엇을 보는지 적는다.

**출처를 밝힌다.** 원저, 편저, 저작권, 내용을 노트 앞에 적는다.

## 5. 검사 절차

**고치기 전에 세어 목록을 만든다.** 고친 뒤에 세면 이미 바꾼 자리가 안 걸려 목록이 불완전해진다.

노션 페이지는 `notion-fetch`로 받는다. 결과가 크면 파일로 떨어지므로 그 파일을 센다.

```bash
python3 - "$F" <<'PY'
import sys, re, collections
s = open(sys.argv[1]).read().replace('\\n', '\n').replace('\\t', '\t')

# 원문 보존 구역을 먼저 뺀다. 코드 블록과 인용문은 검사 대상이 아니다.
body = re.sub(r'```.*?```', '', s, flags=re.S)
body = '\n'.join(l for l in body.split('\n') if not l.strip().startswith('>'))

print('본문 긴 줄', len([l for l in body.split('\n') if '—' in l and '<summary>' not in l]))
print('제목 긴 줄', len([t for t in re.findall(r'<summary>(.{0,90}?)</summary>', body) if '—' in t]))
print('맨 N단계', sum(v for k, v in collections.Counter(
    re.findall(r'구현 [1-6]단계|(?<!구현 )(?<![0-9])[1-6]단계', body)).items() if not k.startswith('구현')))
print('셈 단위', len(re.findall(r'(둘|셋|넷|다섯|여섯|일곱|여덟|아홉|열|열한|열두)[ ]?(자리|곳)', body)))
print('서술형', len(re.findall(r'(한다|이다|된다)[.\n]', body)))
bold = [l for l in body.split('\n') if re.search(r'\*\*[^*\s].*?\*\*', l)
        and '*****' not in l and 'vercel.app' not in l]
print('굵게', len(bold), '줄')
print('가운뎃점', body.count('·'))
print('토글 균형', s.count('<details>'), s.count('</details>'))   # 구조는 전문으로 센다
PY
```


**원문 보존 구역을 먼저 뺀다.** 검사를 걸지 않는 자리가 셋이다.

| 구역 | 왜 |
|---|---|
| 코드 블록 | 실행 당시 프롬프트 원문이다. 고치면 기록이 아니게 된다 |
| 인용문 `> ` | 클로드에게 준 지시다. 서술체가 맞다 |
| 마스킹된 값 `sb_secret_****` | 별표가 굵게로 잡힌다 |
| 와일드카드 주소 | `/**`의 별표가 굵게로 잡힌다 |

**이 셋을 빼지 않으면 위반 수가 부풀려진다.** 5장 C 노트에서 굵게 83건이 잡혔으나 빼고 보니 실제 위반은 0건이었다.

**굵게는 별표 개수가 아니라 줄 수로 센다.** 개수로 세면 마스킹 한 줄이 40건으로 잡힌다.

**토글 쌍만은 전문으로 센다.** 구조는 보존 구역 안팎을 가리지 않는다.

**검사 여섯을 밟는다.**

| 번호 | 무엇 | 검색으로 끝나나 |
|---|---|---|
| 1 | 본문 긴 줄 | 예 |
| 2 | 제목 구분자 | 예 |
| 3 | 단계 표기 혼용 | 아니오. 1차인지 2차인지 문맥으로 가른다 |
| 4 | 셈에 단위가 빠짐 | 예 |
| 5 | 문체가 섞임 | 아니오. 클로드가 판정한다 |
| 6 | 한 동작을 두 낱말로 | 아니오. 클로드가 판정한다 |

**검색으로 끝나지 않는 셋은 목록으로 내고 사람이 채택 여부를 정한다.**

## 6. 걸러야 할 것

**기계적으로 바꾸면 틀리는 자리가 있다. 바꾸기 전에 하나씩 본다.**

| 무엇 | 왜 |
|---|---|
| 「2단계 인증」 | 2차 인증(2FA)이다. 구현 단계가 아니다 |
| 「절차를 2단계로 정함」 | 「두 단계」다. 구현 단계가 아니다 |
| 표의 셀 | 열 제목이 「구현 단계」면 셀은 숫자만으로 갈린다 |
| 규격 문구 인용 | 원문 그대로 두어야 검색된다 |
| 계획서 장 제목 링크 | 저장소 문서를 고쳐야 링크 글자도 바뀐다 |
| 「낱말 — 뜻풀이」 | 쌍점으로 바꾼다 |
| 「절 — 절」 | 쌍점이 어색하다. 한 문장으로 다시 쓴다 |

## 7. 노션을 고칠 때

**사고를 내고 얻은 규칙이다.**

1. 넣기 전에 그 자리 원문을 탭까지 그대로 확인한다
2. 붙일 자리의 앞뒤를 포함한 유일한 문자열을 `old_str`로 잡는다
3. **`<br>`가 든 불릿을 건드리면 그 불릿이 통째로 다시 파싱된다.** 계층이 갈려도 되는지 먼저 정한다
4. 넣은 뒤 이웃 블록이 그대로인지 확인한다
5. `<details>` 쌍이 맞는지 센다
6. 한글을 유니코드 코드값으로 적다 오타를 여러 번 냈다. **넣은 뒤 반드시 되읽는다**
7. 페이지가 커지면 편집이 통째로 막힌다(`rich_text_element_count` 한도)

**한 번에 크게 고치지 않는다.** 168자리를 고칠 때 84개씩 두 번으로 나눴다.

**바꿀 문자열이 길면 창을 좁힌다.** 앞뒤 8자만 잡아도 유일해지는지 먼저 확인한다.

## 8. 보고

`check`는 표만 낸다.

| 무엇 | 몇 | 어디 |
|---|---|---|

`fix`는 고친 뒤에 낸다.

- 고친 것을 표로 낸다
- **안 고친 것과 그 까닭을 함께 낸다**
- 구조가 그대로인지(토글 쌍, 이웃 블록) 확인한 결과를 적는다
- 검색으로 판정되지 않아 사람이 정해야 하는 것을 마지막에 모은다

**과거 실행 기록에는 소급하지 않는다.** `history/`와 `archive/`는 그 시점의 기록이다.
