# 강의 노트 작성 스타일 가이드

> Vibe Coding for DSMP 1~3장에서 추출. Claude가 강의 노트를 작성할 때 이 문서를 먼저 읽고 따를 것.

---

## 1. 종결어미 (가장 중요)

### 원칙: 음슴체가 기본

| 상황 | 채택 | 금지 |
|---|---|---|
| 사실·개념 설명 | ~함, ~됨, ~임, ~있음 | ~합니다, ~됩니다, ~이에요 |
| 실습 지시 | ~클릭, ~실행, ~입력하여 실행 | ~클릭하세요, ~해 주세요 |
| 서술형 안내 | 쓰지 않음 | ~한다, ~나온다, ~합니다 |

서술형(`~한다`)은 원칙적으로 쓰지 않음. 예외가 필요한 자리는 작성자가 직접 판단해 적용.

예시
- ○ 클로드 코드는 같은 엔진에 서로 다른 껍데기를 씌운 두 버전이 존재함
- ○ 설정과 대화 기록도 공유됨
- ○ 터미널에서 아래 명령을 입력하고 실행
- ○ 실습은 3.2 에서 그 안에 만드는 `study01_MNIST(Mac)` 폴더로 다시 엶
- ✗ 클로드 코드에는 두 가지 버전이 있습니다
- ✗ 아래 명령을 입력해 주세요

### 예외: 수강생 직접 지칭 시

"여러분"을 주어로 쓸 때만 평서형 사용
- ○ 여러분은 `C:` 로 나온다

## 2. 구조

### 토글 중첩이 기본 구조

노션의 `<details>` 토글을 다층으로 중첩. summary가 곧 목차 항목.

```
3.1 클로드 데스크톱 설치
  3.1.1 클로드 데스크톱 앱 설치 및 실행
    3.1.1.1 (Homebrew 활용한) 맥 설치 방법
      a) 터미널 열기
      b) Homebrew 확인 및 설치 방법
      c) 클로드 데스크톱 앱 삭제/설치/갱신 방법
        c.1) 신규 설치 방법
        c.2) 갱신 방법
        c.3) 삭제 방법
      d) 실행
```

### 번호 체계

| 레벨 | 형식 | 예 |
|---|---|---|
| 1 | `N.M` | 2.3 PRD 작성 및 4단계 전략 |
| 2 | `N.M.K` | 2.3.1 제품 요건 문서 |
| 3 | `N.M.K.J` | 3.1.1.1 맥 설치 방법 |
| 4 | `a) b) c)` | a) 터미널 열기 |
| 5 | `c.1) c.2)` | c.1) 신규 설치 방법 |

### summary 작성 규칙

- summary 자체에 조건·주의를 괄호로 포함시킴
  - ○ `c.2) 기존 클로드 데스크톱 앱 갱신 방법 (주의: brew 명령으로 설치된 경우에만 작동함)`
- summary는 명사구 또는 동작 지시. 문장으로 끝내지 않음

### 본문

- 불릿(`-`) 위주. 긴 문단 지양
- 한 불릿은 1~2줄
- 줄바꿈은 `<br>` 사용

## 3. 표기 관습

### UI 요소는 백틱

- `홈`, `새로 생성`, `채팅`, `Code`, `예`, `시작하기`
- 파일명·명령어·경로도 백틱: `CLAUDE.md`, `brew --version`, `~/.zprofile`

### 경로 흐름은 화살표

- `홈` → `새로 생성` → `Cowork` → `프로젝트 또는 폴더`
- 시스템 설정 → 키보드 → 키보드 단축키 → 서비스 → 파일 및 폴더

### 강조

- 볼드(`**`)는 쓰지 않음, 강조가 잦으면 강조로 읽히지 않고, 노트 전체가 얼룩짐
- 강조가 꼭 필요한 자리에만 밑줄(`<span underline="true">`)을 씀
- 밑줄을 쓸 자리는 둘 — 놓치면 실습이 막히는 경고, 표 안에서 대비되는 항목
- 강조 대신 항목을 나누거나 표의 열로 분리하는 쪽을 먼저 검토

### 코드블록

언어 지정 필수: `bash`, `powershell`, `plain text`, `javascript`

프롬프트 예시도 코드블록에 넣음 (언어는 `plain text`)

### 어휘는 문어체로

`~/.claude/CLAUDE.md` 6.2절의 구어체, 문어체 대응표를 노트에도 적용함. 종결은 이 문서의 음슴체 규정을 따르고, 어휘만 6.2절을 따름.

예 — 「대어 봄」이 아니라 「대조함」, 「갈림」이 아니라 「구분됨」, 「까닭」이 아니라 「이유」

### 지시가 무엇을 가리키는지 밝힘

`~/.claude/CLAUDE.md` 6.1절의 다섯 규칙을 노트와 대화에도 그대로 적용함. 저것이 정본이고 여기 옮겨 적지 않음.

요약하면 다섯임 — 절 번호 앞에 문서 이름, 셈에 단위, 같은 것을 한 낱말로, 목적어 생략 금지, 은유 동사 대신 동작 동사.

노트에서 특히 걸리는 자리 둘

- **토글 제목에 있는 것을 본문에서 생략하지 않음.** 토글이 접히면 제목이 안 보이고, 인용될 때도 따라오지 않음
- **`a)`, `c.1)` 같은 번호만으로 가리키지 않음.** "위의 c)에서" 대신 "c) 프롬프트 실행에서"로 적음

## 5. 필수 서술 패턴

### ① 실패 케이스 선제 안내

명령을 제시할 때 성공/실패 분기를 항상 함께 제시.

```
- `Homebrew 4.x.x` 처럼 버전이 표시되면 다음으로 진행
- `command not found: brew`라고 나오면 아래와 같이 설치
```

### ② 괄호 부연

소요 시간, 주의사항, 예외 조건을 괄호로 덧붙임.

```
(5~10분 소요, 중간에 맥 로그인 암호를 입력, 암호는 화면에 표시되지 않으니 그냥 입력하고 엔터)
(이 절차는 애플 실리콘(M칩) 맥에서만 진행되고, 인텔 맥에서는 진행되지 않음)
```

### ③ 화면 캡처 환경 차이 고지

스크린샷과 수강생 환경이 다를 수 있으면 반드시 사전 안내.

```
- 아래 화면은 맥을 네트워크 드라이브로 연결한 상태라 경로가 `Z:` 로 보인다. 여러분은 `C:` 로 나온다.
- 일부 화면이 윈도우에서 캡처되었으나, 맥과 큰 차이가 없음
```

### ④ 비교는 표로

두 개 이상 선택지를 다룰 때 산문 대신 표. 헤더에 볼드를 넣지 않음.

| | CLI 버전 | 데스크톱 앱 |
|---|---|---|
| 실행 위치 | 터미널에서 `claude` 명령 | 별도 앱(맥, 윈도우) |

### ⑤ 막힐 때의 탈출구 제시

```
- 방법 2에서 의존 패키지(VCLibs 등)가 없다는 오류가 나면, 그 오류 메시지를 클로드에게 그대로 붙여 넣어 해결 요청
```

### ⑥ 다음 차시 예고

각 장 끝 "정리" 섹션 마지막 줄.

```
- 다음 시간에는 클로드 코드 설치 및 활용 실습으로 진행할 예정
```

## 8. 금지 사항

- ✗ "~합니다", "~해 주세요" 등 존댓말 종결 (여러분 지칭 시 제외)
- ✗ "매우", "정말", "굉장히" 등 강조 부사
- ✗ "~할 수 있습니다" 남용 → "~할 수 있음" 또는 "~가능함"
- ✗ 도입부 인사말, 마무리 격려 문장
- ✗ 이모지
- ✗ 3줄 이상의 산문 문단 (불릿 또는 표로 분해)
- ✗ 실패 케이스 없이 성공 경로만 서술
- ✗ 스크린샷 환경 차이를 언급하지 않고 넘어가기
- ✗ 볼드(`**`) 사용 — 강조가 필요하면 밑줄을 절제해 쓰거나 항목을 나눔
- ✗ 서술형 종결(`~한다`, `~나온다`) — 예외는 작성자가 직접 적용

## 9. 작성 후 자체 검증

작성을 마치면 아래를 스스로 점검하고, 어긋난 부분을 지적한 뒤 수정할 것.

1. 종결어미가 음슴체로 통일되었는가?
2. 명령 제시마다 실패 케이스 분기가 있는가?
3. UI 요소에 백틱이 적용되었는가?
4. 용어 사전과 어긋나는 표기가 있는가?
5. 3줄 넘는 산문 문단이 남아 있는가?
6. 볼드가 남아 있지 않은가? 밑줄이 꼭 필요한 자리에만 쓰였는가?
7. 7절 예시와 나란히 놓았을 때 이질감이 없는가?
8. 절 번호 앞에 문서 이름이 붙었는가? 셈에 단위가 밝혀졌는가? (`~/.claude/CLAUDE.md` 6.1절)
9. 목적어를 생략한 문장, 은유 동사, 같은 것을 두 낱말로 부른 자리가 남아 있지 않은가?
