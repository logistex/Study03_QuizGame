`questions.js`의 문항을 규격에 대고 검증한다.

검증 기준은 여기서 새로 만들지 않는다. 근거는 `spec/PRD.md` 3.6절(작성 규칙), 4.2절(데이터 검사), 6절 1단계(육안 검토)와 `history/12-question-guidelines.md`다. 판정이 갈리면 그 문서를 열어 확인하고, 이 파일의 요약을 근거로 삼지 않는다.

## 인수

받은 인수는 `$ARGUMENTS`이다.

| 받은 인수 | 대상 |
|---|---|
| 비어 있음 | 네 카테고리 전체 |
| `한국사` 또는 `korean_history` | 한국사 |
| `과학` 또는 `science` | 과학 |
| `지리` 또는 `geography` | 지리 |
| `예술과 문화` 또는 `art_culture` | 예술과 문화 |

이름과 id 중 어느 쪽으로 받아도 같게 취급한다. 어느 카테고리에도 걸리지 않으면 여기서 멈추고, 받은 값과 고를 수 있는 네 가지를 적어 되묻는다. 임의로 하나를 골라 진행하지 않는다.

## 1. 자동 검사

`script.js`의 `validateData()`를 Node로 그대로 돌린다. **검사 로직을 다시 쓰지 않는다.** 브라우저가 로드 시점에 도는 것과 같은 함수라야 규격과 코드와 이 명령어가 어긋나지 않는다.

```bash
node -e "
const fs = require('fs'), vm = require('vm');
const ctx = vm.createContext({ console, document: { addEventListener() {} } });
vm.runInContext(fs.readFileSync('questions.js', 'utf8'), ctx);
vm.runInContext(fs.readFileSync('script.js', 'utf8'), ctx);
const errors = vm.runInContext('validateData()', ctx);
console.log(errors.length ? errors.join('\n') : '검사 통과: 위반 0건');
"
```

- `document` 스텁은 `script.js` 마지막 줄의 `DOMContentLoaded` 등록 때문에 둔다. 검사와는 무관하다.
- 이 함수는 **언제나 네 카테고리 전체를 돈다.** 카테고리 인수를 받았으면 출력에서 그 카테고리의 문항 `id`로 시작하는 줄만 추린다. 함수에 범위를 넣으려고 고치지 않는다.
- 출력된 줄은 해석하지 말고 그대로 보고에 옮긴다. `kh_07: options 길이가 3` 꼴이 이미 문항과 위반 항목을 담고 있다.
- 위반이 나와도 2절과 3절은 그대로 진행한다. 자동으로 걸리는 것과 사람이 보는 것은 겹치지 않으므로, 여기서 멈추면 한 번에 알 수 있는 것을 두 번에 나눠 알게 된다.

여기서 잡히는 항목은 PRD 4.2절 2번 표에 있는 열한 가지다. 그 목록을 이 파일에 옮겨 적지 않는다. 함수가 기준이다.

## 2. 사람이 봐야 하는 것

아래는 **데이터가 검사를 통과하고 화면도 정상인 채로 틀릴 수 있는 것들**이다. 통과, 차단으로 판정할 수 없어 검사 함수에 넣지 않기로 한 항목이다(`history/12-question-guidelines.md` 4절).

| 확인할 것 | 근거 |
|---|---|
| `options[answer]`가 실제 정답을 가리키는가 | PRD 6절 1단계 |
| 해설이 그 정답의 근거를 설명하는가 | PRD 6절 1단계 |
| 정답이 하나로만 읽히는가. 오답 셋이 모두 명백한 오답인가 | PRD 3.6절 |
| 최상급 표현에 재는 기준이 문항에 적혀 있는가 | PRD 3.6절 |
| 시점과 범위가 한정되어 있는가. 시점에 따라 달라지는 수치라면 해설에 기준 시점이 있는가 | PRD 3.6절 |
| 문제 텍스트와 해설이 선택지의 위치를 지칭하지 않는가 | PRD 2.1절, 3.6절 |
| 논란이 있는 내용을 주류 학설 기준으로 썼는가 | 12번 문서 2절 |
| `question`이 60자, 각 선택지가 20자를 넘지 않는가 | PRD 3.6절 필드 표. **검사 함수에 이 항목이 없다.** 자동으로 걸리지 않으므로 여기서 센다 |

`ge_09`의 "국토 면적이 세계에서 가장 넓은 나라", `ge_04`의 "남한에서 가장 긴 강"이 넷째, 다섯째 줄의 본보기다.

문항 하나만 보아서는 판정되지 않는 것은 4절에서 따로 본다.

## 3. 나눠서 확인한다

2절의 항목과 아래 출처 대조를 **문항 4개씩 묶어 갈래마다 서브에이전트 하나에 맡긴다.** 40문항이면 10갈래, 한 카테고리면 3갈래(4, 4, 2)다.

한 갈래가 열 문항을 차례로 맡으면 그 갈래의 소요가 전체 소요가 된다. 카테고리별로 4갈래만 나눠 40분 넘게 돌다 결과 없이 끊긴 기록이 있다(`history/32-question-source-verification-report.md` 4절). 갈래 수를 늘리고 갈래마다 주는 일을 가볍게 유지한다.

### 각 갈래에 줄 것

- 맡을 문항 4개의 전체 필드(`id`, `question`, `options`, `answer`, `difficulty`, `explanation`)를 프롬프트에 그대로 넣는다. 파일을 찾아 읽으라고 하지 않는다.
- 2절의 확인 항목.
- 아래 출처 규칙.
- 결과 파일 경로.

### 출처 규칙

- **해설에 나오는 연도, 수치, 인명은 외부 출처 두 곳 이상으로 대조한다.** 두 출처는 서로 다른 도메인이어야 한다.
- **기억으로 판정하지 않는다.** "알고 있는 사실과 맞다"는 확인이 아니다. 작성자와 검토자가 같은 오해를 공유하면 그대로 통과한다는 것이 12번 문서 3절의 지적이다.
- 두 곳을 채우지 못했으면 맞다고도 틀리다고도 적지 않고 **`미확인`** 으로 적는다. 무엇을 못 찾았는지 한 줄로 남긴다.
- 자료에 따라 서술이 갈리면 어느 쪽을 골랐는지와 그 근거를 함께 적는다. 12번 문서 3절이 `kh_07`, `kh_09`, `ac_10`, `ge_02`, `sc_10` 다섯을 이미 그런 자리로 지목했다.
- 문항당 검색은 한두 번으로 끝낸다.

### 결과 파일을 먼저 쓴다

각 갈래는 **결과를 파일로 쓴 다음에 응답한다.** 서브에이전트는 실패해도 조용하고, 파일이 없으면 부분 결과조차 회수되지 않는다.

```
doc/verify/<YYYY-MM-DD>-<카테고리 또는 all>-batch-NN.md
```

파일에 문항마다 다음을 적는다.

| 문항 | 판정 | 확인한 출처 | 적을 것 |
|---|---|---|---|
| `kh_01` | 통과 / 지적 / 미확인 | URL 둘 이상 | 지적이면 무엇이 어떻게 어긋나는지 |

응답으로는 지적과 미확인만 요약한다. 통과 문항을 응답에 늘어놓지 않는다.

갈래가 모두 끝나면 **파일 수가 나눈 갈래 수와 같은지 확인한다.** 모자라면 그 갈래만 다시 돌린다. 응답이 없는 갈래를 통과로 세지 않는다.

## 4. 취합과 보고

먼저 문항 하나만 보아서는 판정되지 않는 것을 대상 카테고리마다 확인한다.

| 확인할 것 | 근거 |
|---|---|
| 난이도 배분이 초급 4, 중급 4, 고급 2를 기준으로 하는가. 합만 맞으면 다른 조합도 된다 | PRD 3.6절 |
| 정답 인덱스 0부터 3까지가 각각 2~3회씩 나오는가 | PRD 3.6절 |
| 텍스트가 달라도 같은 사실을 묻는 문항이 있는가 | 12번 문서 5절. 검사 함수는 `question` 텍스트가 똑같을 때만 잡는다 |

그다음 보고를 쓴다.

- 1절의 자동 검사 결과 — 위반 건수와 출력된 줄.
- 3절의 지적 — 문항, 무엇이 어긋나는지, 근거 절, 확인한 출처.
- 3절의 미확인 — 문항과 못 찾은 것.
- 이 절의 카테고리 단위 확인 결과.
- 갈래 수와 회수한 결과 파일 수.

### 고치지 않는다

**`questions.js`를 비롯한 문제 파일을 이 명령어로 고치지 않는다.** 이 명령어는 무엇이 어긋났는지를 알리는 자리다. 고칠지는 보고를 받은 사람이 정한다.

**걸린 것이 하나도 없으면 "고칠 것 없음"이라고 적는다.** 12번 문서가 40문항을 훑고도 "지금 고칠 것은 없다"로 닫은 것과 같다. 통과를 통과라고 적지 않고 개선 제안으로 채우면, 다음 사람이 무엇이 실제 지적인지 가려내야 한다.
