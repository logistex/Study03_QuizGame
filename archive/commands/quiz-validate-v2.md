`questions.js`의 문제를 검증한다. 대상 범위는 `$ARGUMENTS`이며, 비어 있으면 40문항 전체를 본다.
카테고리는 `korean_history`, `science`, `geography`, `art_culture` 또는 한국사, 과학, 지리, 예술과 문화로 받는다.

이 명령어는 **새 검증 기준을 만들지 않는다.** 기준은 이미 규격에 있고, 여기서는 그것을 실행할 뿐이다.

## 1. 자동 검사부터 돌린다

PRD 4.2절의 검사 항목은 `script.js`의 `validateData()`가 이미 구현하고 있다.
**검사 로직을 다시 짜지 않는다.** Node로 그 함수를 그대로 돌려 결과를 받는다.
위반이 있으면 `id`와 항목을 그대로 옮긴다.

## 2. 자동으로 잡히지 않는 것을 본다

PRD 3.6절 끝이 "위 세 규칙은 자동 검사로 판정할 수 없다"고 못박은 것들이다.
문항마다 다음을 묻고, 걸리는 것만 보고한다.

| 볼 것 | 판정 기준 | 규격 |
|---|---|---|
| 정답이 하나로만 읽히는가 | 오답 셋이 모두 명백한 오답인가. 다른 해석이 가능하면 문제 텍스트에 조건이 밝혀져 있는가 | 3.6절 |
| 최상급 표현에 재는 기준이 있는가 | "가장 큰", "가장 높은"에 면적인지 인구인지, 해발인지 기저부터인지가 붙어 있는가. `ge_09`가 본보기 | 3.6절 |
| 시점과 범위가 한정되어 있는가 | 시점에 따라 달라지는 수치라면 해설에 기준 시점이 있는가. 지리적, 분류적 범위가 좁혀져 있는가. `ge_04`가 본보기 | 3.6절 |
| 선택지 위치를 지칭하지 않는가 | "위의", "첫 번째" 같은 표현이 문제나 해설에 없는가 | 2.1절 |

교차 검증의 관점은 `history/12-question-guidelines.md`를 따른다.

## 3. 사실 확인

해설에 담긴 연도, 수치, 인명은 **외부 출처 두 곳 이상으로 대조한다.**

- **기억만으로 판정하지 않는다.**
- 출처가 갈리면 갈린 사실을 그대로 적는다. 한쪽으로 정리하지 않는다
- 확인하지 못한 것은 "미확인"으로 남긴다. 확인한 척하지 않는다

## 4. 보고

- **문제 파일을 직접 고치지 않는다.** 고칠지는 사람이 정한다
- 걸린 것이 없으면 "고칠 것 없음"이라고 적는다. 이것도 점검 결과다
- 걸린 것은 `id`, 무엇이 어긋나는지, 권고하는 수정 문구 순으로 적는다
