# 상식 퀴즈 게임 PRD

> 1차 검토 반영본이다. 개정 전 판본을 보존한 것이며, 현재 문서는 [PRD.md](../spec/PRD.md)를 볼 것.

## 1. 개요

### 1.1 목적

4지선다 객관식 상식 퀴즈 게임을 만든다. 플레이어는 이름을 입력하고 카테고리를 골라 문제를 풀며, 답을 고르는 즉시 정답 여부와 해설을 확인한다. 한 판이 끝나면 최종 점수를 확인하고, 기록이 상위권에 들면 순위표에 이름이 남는다.

### 1.2 대상 사용자

- 로그인이나 회원 가입 없이 바로 즐기려는 개인 사용자
- 브라우저에서 파일을 열기만 하면 실행되는 환경을 원하는 사용자

### 1.3 기술 스택

| 항목 | 선택 |
|---|---|
| 언어 | Vanilla JavaScript (ES6+) |
| 마크업, 스타일 | HTML5, CSS3 |
| 데이터 저장 | `localStorage` |
| 문제 데이터 | `questions.js` (전역 상수 선언) |
| 외부 라이브러리 | 없음 |
| 실행 방식 | `index.html`을 브라우저에서 직접 열기 (`file://`) |

### 1.4 파일 구성

| 파일 | 역할 |
|---|---|
| `index.html` | 네 화면(시작, 퀴즈, 결과, 순위표)의 마크업을 모두 담는다 |
| `style.css` | 전체 스타일과 반응형 레이아웃 |
| `questions.js` | 카테고리 정의와 40문제 데이터 |
| `script.js` | 게임 상태 관리, 화면 전환, 채점, 순위 저장, 순위표 렌더링 |

`index.html` 머리에서 `style.css`를 연결하고, 하단에서 `questions.js`를 먼저, `script.js`를 나중에 읽는다.

```html
<link rel="stylesheet" href="style.css">
...
<script src="questions.js"></script>
<script src="script.js"></script>
```

### 1.5 문제 데이터를 JSON이 아닌 JS 파일로 두는 이유

`file://` 프로토콜로 페이지를 열면 브라우저의 보안 정책 때문에 `fetch('questions.json')`이 차단된다. 별도 서버 없이 실행해야 하므로, 문제 데이터를 `questions.js` 안의 전역 상수로 선언하고 `<script>` 태그로 읽어 들인다. 이렇게 하면 로컬 서버나 빌드 도구가 필요하지 않다.

## 2. 게임 규칙

- 4지선다 객관식이다.
- 카테고리는 한국사, 과학, 지리, 예술과 문화 네 가지다.
- 카테고리마다 10문제씩, 모두 40문제를 보유한다.
- 플레이 모드는 두 가지다.
  - **카테고리별 도전**: 고른 카테고리의 10문제를 푼다. 만점은 10점이다.
  - **전체 도전**: 네 카테고리 40문제를 섞어서 푼다. 만점은 40점이다.
- 문제 순서는 판을 시작할 때마다 섞는다. 선택지 순서도 문제를 보여 줄 때마다 섞는다.
- 정답은 1점, 오답은 0점이다. 난이도는 배점에 영향을 주지 않는다.
- 답을 고르면 즉시 정답 여부와 해설을 보여 주고, 그 문제는 다시 고를 수 없다.
- 한 판이 끝나면 최종 점수와 정답률을 보여 주고, 상위권 기록이면 순위표에 남긴다.

### 2.1 셔플 규칙

문제 순서와 선택지 순서를 섞을 때는 모두 Fisher-Yates 알고리즘을 쓴다.

```javascript
function shuffle(arr) {
  const a = arr.slice();
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    [a[i], a[j]] = [a[j], a[i]];
  }
  return a;
}
```

`sort(() => Math.random() - 0.5)`는 쓰지 않는다. 비교 결과가 호출할 때마다 달라져 순서가 고르게 섞이지 않고, 정답이 특정 자리에 더 자주 남는다. 섞이기는 하므로 화면으로는 이상을 알아챌 수 없다.

선택지를 섞으면 규칙 둘이 따라온다.

- 선택지를 섞은 뒤에는 `answer`를 정답 텍스트의 새 인덱스로 갱신한다. 갱신을 빠뜨려도 화면은 정상으로 보이므로 채점만 조용히 틀린다.
- 문제 텍스트와 해설은 선택지의 위치를 지칭하지 않는다. "위의 두 번째 보기는"과 같은 표현은 섞는 순간 사실과 어긋난다. 이 규칙은 문제 데이터를 쓰는 1단계에서 지켜야 한다.

## 3. 기능 요구사항

### 3.1 시작 화면

- 게임 제목을 표시한다.
- 플레이어 이름 입력란을 둔다.
  - 앞뒤 공백을 잘라 낸 뒤 길이를 재며, 최대 12자까지 받는다.
  - 잘라 낸 결과가 비어 있으면 게임을 시작할 수 없고, "이름을 입력해 주세요."를 표시한다.
- 카테고리 카드 네 개를 표시한다. 각 카드에는 카테고리 이름과 문제 수를 적는다. 문제 수는 `QUESTIONS[id].length`를 세어 그리며, 숫자를 마크업에 직접 쓰지 않는다.
- "전체 도전 (40문제)" 버튼을 별도로 둔다.
- "순위표 보기" 버튼을 두어 저장된 기록을 확인할 수 있게 한다.
  - 이름을 입력하지 않아도 순위표를 볼 수 있다.
  - 순위표 화면에서 돌아오면 입력해 둔 이름이 그대로 남아 있다.
- 카드나 전체 도전 버튼을 누르면 해당 모드로 퀴즈를 시작한다.

### 3.2 퀴즈 진행 화면

화면 상단에 다음을 표시한다.

- 진행 상황 (예: `3 / 10 문제`)
- 현재 점수 (예: `2 / 10`). 진행 상황과 표기를 맞춰 전체에서 어디쯤인지 함께 읽히게 한다.
- 현재 문제의 카테고리 이름과 난이도 배지

난이도 배지는 CSS 클래스로 색을 구분한다.

| 난이도 | 클래스 | 색 계열 | 화면 라벨 |
|---|---|---|---|
| `easy` | `diff-easy` | 초록 | 초급 |
| `medium` | `diff-medium` | 파랑 | 중급 |
| `hard` | `diff-hard` | 주황 | 고급 |

본문에는 문제 텍스트와 선택지 버튼 네 개를 둔다. 상단에는 "그만두기" 버튼을 둔다.

선택지를 누른 뒤의 동작은 다음과 같다.

- 네 버튼을 모두 비활성화해 재선택을 막는다.
- 정답 버튼을 초록색으로 강조하고 ✓를 함께 표시한다.
- 오답을 골랐다면 고른 버튼을 빨간색으로 강조하고 ✗를 함께 표시한다. 색만으로 구분하지 않는다.
- 피드백 문구를 표시한다. 정답이면 "정답입니다.", 오답이면 "오답입니다. 정답은 ○○입니다."로 적으며, ○○ 자리에는 정답 선택지의 텍스트를 넣는다.
- 해설 영역을 펼쳐 해당 문제의 해설을 보여 준다.
- "다음 문제" 버튼을 노출한다. 마지막 문제에서는 "결과 보기"로 표시한다.
- 버튼이 화면에 들어오도록 스크롤하고 초점을 준다. 해설이 펼쳐지면 모바일에서 버튼이 화면 밖으로 밀리는데, 눌러야 넘어가는 구조라 그대로 두면 게임이 멈춘 것처럼 보인다.

"다음 문제"를 누른 뒤의 동작은 다음과 같다.

- 버튼을 즉시 숨기고 다음 문제를 그린 뒤 다시 노출한다. 연타로 문제를 건너뛰는 것을 막는다.
- 스크롤을 문제 영역 상단으로 되돌린다. 앞 문제에서 내려간 위치 그대로 두면 다음 문제가 중간부터 보인다.

자동으로 다음 문제로 넘어가지 않는다. 해설을 읽을 시간이 필요하므로, 플레이어가 버튼을 눌러야 넘어간다.

"그만두기"를 누르면 확인창을 띄우고, 확인하면 기록을 남기지 않은 채 시작 화면으로 돌아간다. 전체 도전 40문제를 시작하면 끝낼 때까지 나갈 수 없는 상태를 막기 위한 것이다.

진행 중에 새로고침하거나 페이지를 닫으려 하면 확인창을 띄운다. 이어 하기는 범위 밖이므로(7절), 실수로 진행 상황을 날리는 것만 막는다.

### 3.3 결과 화면

- 최종 점수를 표시한다 (예: `8 / 10 정답`).
- 정답률을 백분율로 표시한다. 소수점 첫째 자리에서 반올림한 정수로 적는다.
- 플레이어 이름과 플레이한 모드를 함께 표시한다.
- 해당 모드의 순위표를 함께 표시한다. 카테고리별 도전이면 그 카테고리의 5줄, 전체 도전이면 통합 순위표 10줄만 보여 준다.
- 순위표 진입 여부에 따라 다음과 같이 표시한다.
  - 진입했으면 "순위표 N위 진입"을 표시하고, 순위표에서 이번 기록에 해당하는 줄을 강조한다. N과 강조할 줄은 저장 함수가 돌려준 삽입 위치로 정한다(3.4절).
  - 진입하지 못했으면 "순위표에 들지 못했습니다."를 표시하고, 강조 없이 순위표만 보여 준다.
- 버튼 두 개를 둔다.
  - "다시 도전": 같은 모드를 새로 섞어 다시 시작한다. 이름은 직전 판의 이름을 그대로 쓴다.
  - "처음으로": 시작 화면으로 돌아간다.

### 3.4 순위 기록

순위표는 두 종류를 관리한다.

| 순위표 | 대상 | 보관 수 | 만점 |
|---|---|---|---|
| 카테고리별 | 카테고리별 도전 결과 | 카테고리마다 상위 5개 | 10점 |
| 통합 | 전체 도전 결과 | 상위 10개 | 40점 |

만점이 다른 두 결과를 한 표에 섞으면 비교가 성립하지 않으므로, 모드에 따라 기록할 순위표를 나눈다.

- 같은 이름의 기록도 합치지 않고 판마다 별개로 쌓는다. 순위표는 사람 목록이 아니라 도전 기록이다.
- 새 기록은 목록 맨 앞에 넣은 뒤 점수 내림차순으로만 정렬한다. 동점이면 최근 기록이 위에 온다.
- 이 방식은 정렬이 안정 정렬(같은 값이면 원래 순서를 유지하는 정렬)임을 전제로 한다. `Array.prototype.sort`는 ES2019부터 안정 정렬이 표준으로 보장되고, 대상 브라우저가 최신 Chrome, Edge, Safari이므로 그대로 의존한다. 비교 함수에 동점 처리를 넣지 않는다.
- 보관 수를 넘어서면 가장 낮은 기록을 지운다.
- 저장 함수는 정렬과 자르기를 마친 뒤, 이번 기록이 목록에 남아 있으면 그 인덱스를, 잘려 나갔으면 `null`을 돌려준다. 결과 화면은 이 값으로 진입 여부와 강조할 줄을 정한다. 이름과 점수로 줄을 되찾으려 하면 같은 이름, 같은 점수의 기록과 구별되지 않는다.
- 저장 항목은 플레이어 이름, 점수, 총 문제 수, 달성 날짜다. 날짜는 로컬 시간대를 기준으로 `YYYY-MM-DD` 형식으로 만든다.

`localStorage` 저장 구조는 다음과 같다. 키는 `quizGameRankings` 하나를 쓴다.

```json
{
  "korean_history": [
    { "name": "홍길동", "score": 9, "total": 10, "date": "2026-08-10" }
  ],
  "science": [],
  "geography": [],
  "art_culture": [],
  "all": [
    { "name": "홍길동", "score": 34, "total": 40, "date": "2026-08-10" }
  ]
}
```

`file://`로 열면 같은 컴퓨터의 다른 로컬 페이지와 저장소를 공유한다. 다른 실습 파일이 키를 덮어쓰지 않도록 `quizGameRankings`라는 이름을 그대로 유지한다.

### 3.5 순위표 화면

- 시작 화면의 "순위표 보기" 버튼으로 진입한다.
- 카테고리별 순위표 네 개와 통합 순위표를 함께 보여 준다.
- 열은 순위, 이름, 점수, 날짜 네 가지다. 동점이어도 순위 번호는 줄 순서대로 매긴다.
- 이름은 `textContent`로 넣는다. 플레이어가 입력한 값이 마크업으로 해석되지 않게 한다.
- 기록이 없는 순위표에는 "아직 기록이 없습니다."를 표시한다.
- "기록 지우기" 버튼을 두어 저장된 순위를 모두 지울 수 있게 한다. 누르면 확인창을 한 번 띄운다.
- "닫기" 버튼으로 시작 화면으로 돌아간다.

### 3.6 문제 데이터 (`questions.js`)

카테고리 정의와 문제 데이터를 각각 전역 상수로 선언한다.

```javascript
const CATEGORIES = [
  { id: 'korean_history', name: '한국사' },
  { id: 'science',        name: '과학' },
  { id: 'geography',      name: '지리' },
  { id: 'art_culture',    name: '예술과 문화' }
];

const QUESTIONS = {
  korean_history: [
    {
      id: 'kh_01',
      question: '조선을 건국한 인물은 누구인가?',
      options: ['이성계', '이방원', '정도전', '왕건'],
      answer: 0,
      difficulty: 'easy',
      explanation: '이성계는 1392년 고려를 무너뜨리고 조선을 세워 태조가 되었다.'
    }
    // ... 카테고리마다 10문제
  ],
  science: [],
  geography: [],
  art_culture: []
};
```

필드 규칙은 다음과 같다.

| 필드 | 설명 |
|---|---|
| `id` | 문제 식별자. 카테고리 약어와 두 자리 번호를 잇는다 (`kh_01`, `sc_07`) |
| `question` | 문제 텍스트. 60자를 넘기지 않는다 |
| `options` | 선택지 네 개의 배열. 각 선택지는 20자를 넘기지 않는다 |
| `answer` | 정답의 인덱스 (0~3) |
| `difficulty` | `'easy'`, `'medium'`, `'hard'` 중 하나 |
| `explanation` | 해설. 한두 문장으로 정답의 근거를 설명한다 |

카테고리 약어는 `kh`(한국사), `sc`(과학), `ge`(지리), `ac`(예술과 문화)를 쓴다.

난이도 값을 영문 키로 두는 이유는 배지 색상을 CSS 클래스로 구분하기 위해서다. 화면에 보이는 "초급, 중급, 고급" 라벨은 `script.js`에서 매핑한다.

데이터를 작성할 때 다음을 지킨다.

- 난이도 배분은 카테고리마다 초급 4문제, 중급 4문제, 고급 2문제를 기준으로 한다. 합이 10이면 다른 조합도 된다.
- 정답 인덱스를 고루 흩는다. 카테고리마다 0부터 3까지가 각각 2~3회씩 나오게 배치한다. 선택지를 섞기는 하지만, 데이터 자체가 한쪽으로 쏠려 있으면 문제를 검토하기 어렵다.
- 문제 텍스트와 해설에 선택지의 위치를 지칭하는 표현을 쓰지 않는다(2.1절).

## 4. 비기능 요구사항

| 항목 | 내용 |
|---|---|
| 실행 | 별도 서버나 빌드 없이 `index.html`을 열어 동작한다 |
| 외부 의존성 | 없다. 웹 폰트, CDN, 라이브러리를 쓰지 않는다 |
| 반응형 | 모바일 세로 화면과 데스크톱을 모두 지원한다 |
| 브라우저 | 최신 Chrome, Edge, Safari를 기준으로 한다 |

### 4.1 에러 처리

1. **`questions.js` 로드 실패**: `QUESTIONS`가 정의되지 않았으면 시작 화면에 "문제 데이터를 불러오지 못했습니다."를 표시하고 게임 시작을 막는다.
2. **문제 데이터 검사**: 시작할 때 카테고리별 문제 수, `options.length === 4`, `0 <= answer <= 3`을 확인하고 어긋나면 시작을 막는다. 선택지가 셋만 들어가도 에러 없이 채점만 틀리기 때문이다.
3. **`localStorage` 사용 불가**: 사파리 비공개 모드 등에서 저장이 막힐 수 있다. 읽기와 쓰기를 `try/catch`로 감싸고, 실패하면 순위 저장만 건너뛴 채 게임은 정상 진행한다. 결과 화면과 순위표 화면에 "이 브라우저에서는 순위 기록을 저장할 수 없습니다."를 표시한다.
4. **저장 데이터 손상**: 읽은 값이 예상한 형태가 아니면 빈 순위표로 초기화하고 계속 진행한다.
### 4.2 접근성

- 선택지 버튼에 키보드 초점이 보이도록 한다.
- 선택지 버튼은 최소 높이 44px로 하고, 글이 길면 줄바꿈해 전부 보이게 한다. 잘라 내지 않는다.
- 정답과 오답을 색만으로 구분하지 않는다. ✓와 ✗를 함께 표시한다(3.2절).
- 피드백 문구와 해설 영역에 `aria-live="polite"`를 준다. 정답 여부가 소리로 전달되지 않으면 화면을 보지 못하는 사용자는 다음 문제로 넘어갈 판단을 할 수 없다.

## 5. 화면 흐름

```
[시작 화면]
  이름 입력 → 카테고리 카드 선택 또는 전체 도전
        │                                    └─→ [순위표 화면] ─→ 시작 화면
        ▼
[퀴즈 진행 화면]
  문제 표시 → 선택지 클릭 → 즉시 피드백 + 해설 → "다음 문제"
        │                                              │
        │      └─ "그만두기" → 확인 → 시작 화면 (기록 없음)
        │                                              │
        └──────────── 남은 문제 있음 ←─────────────────┘
        │ 마지막 문제 완료
        ▼
[결과 화면]
  점수, 정답률, 순위표 진입 여부
        ├─ "다시 도전" → 퀴즈 진행 화면 (같은 모드, 새로 섞음)
        └─ "처음으로"  → 시작 화면
```

## 6. 구현 단계

각 단계에서 화면을 만들 때 그 화면의 스타일도 함께 쓴다. `style.css`를 마지막에 몰아 쓰지 않는다.

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | `questions.js` 작성 | 네 카테고리에 10문제씩, 모든 문제에 난이도와 해설이 채워져 있고 3.6절의 작성 규칙을 지킨다 |
| 2 | `index.html` 골격과 시작 화면 | 이름 입력, 카테고리 카드, 전체 도전 버튼이 보이고 화면 전환이 동작한다 |
| 3 | 퀴즈 진행과 즉시 피드백 | 문제와 선택지가 섞여 나오고, 정답, 오답 강조와 해설이 표시되며 점수가 누적된다 |
| 4 | 결과 화면과 순위 기록, 순위표 화면 | 최종 점수가 나오고 `localStorage`에 순위가 저장되며, "순위표 보기"로 다섯 개 순위표를 확인할 수 있고, 다시 열어도 기록이 남아 있다 |
| 5 | 반응형 마무리와 에러 처리 | 모바일 폭에서 레이아웃이 깨지지 않고, 4.1의 네 상황과 4.2의 접근성 항목이 처리된다 |
| 6 | 문제 추가 출제 | 커스텀 명령어로 문제를 추가해도 3.6절의 작성 규칙과 데이터 검사를 통과한다 |

1단계는 다섯 단계 중 가장 무거운 작업이므로 문제를 카테고리마다 10개만 쓰고, 돌아가는 게임을 먼저 확인한 뒤 6단계에서 늘린다.

## 7. 범위에서 제외한 것

다음은 이번 구현에 넣지 않는다. 각 항목에 제외한 이유를 함께 적는다.

- **제한 시간(타이머)과 시간 기반 점수 가중치** — 해설을 읽고 넘어가는 흐름(3.2절)과 맞지 않는다. 시간에 쫓기면 해설을 읽지 않게 된다.
- **난이도별 배점 차등, 난이도 필터 선택** — 배점을 난이도로 나누면 몇 문제를 맞혔는지가 점수에서 보이지 않는다. 난이도 데이터는 그대로 보관하므로 나중에 붙일 수 있다.
- **오답 노트, 틀린 문제만 다시 풀기** — 한 판이 끝난 뒤에도 어느 문제를 틀렸는지 남겨 두어야 하므로 저장 구조(3.4절)가 순위 기록보다 커진다.
- **다음 방문 시 마지막 이름 자동 입력** — 이름은 판을 넘어 유지되며 "처음으로"를 누를 때까지 바뀌지 않는다(3.3절). 브라우저를 닫았다 다시 열었을 때 복원하는 것만 제외한다.
- **진행 중 새로고침 시 이어 하기** — 진행 상황을 저장해야 하므로 저장 구조가 커진다. 실수로 날리는 것은 확인창으로 막는다(3.2절).
- **사운드 효과, 화면 전환 애니메이션** — 이런 퀴즈 게임에서는 없어도 진행에 지장이 없다. 만드는 분량만 늘어난다.
- **서버 연동, 온라인 순위표, 문제 데이터 원격 갱신** — 별도 서버 없이 `index.html`을 열어 실행한다는 전제(1.3절)를 깬다.
- **문제은행 확대** — 카테고리마다 20문제 이상으로 늘리고 그중 10개를 뽑는 방식이 정석이나, 데이터 작성 분량 때문에 이번 범위에서 제외한다. 따라서 같은 카테고리를 반복하면 같은 문제 구성이 나온다.
