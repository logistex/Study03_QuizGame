아래 상자 안의 것을 그대로 넣었다.

```
spec/PRD.md를 2차 구현에 맞게 고쳐 줘.

## 근거

무엇을 정했는지는 history/impl_v2/55-phase2-design-decisions.md에 있다.
그 문서를 먼저 읽고, 거기 적힌 것만 근거로 쓴다. 대화에서 오간 기억이나
네가 아는 일반적인 설계는 근거가 아니다.

**근거 문서를 고치지 않는다.** 55번에 고칠 것이 보이면 고치지 말고 보고에
적는다. 근거를 고치면서 그 근거로 규격을 고치면, 나중에 대조할 때 어긋난
자리가 보이지 않는다.

## 고칠 절

- 1.3 기술 스택 — 정적 파일 넷에서 서버와 DB가 붙는 구성으로
- 1.4 파일 구성 — 서버 함수 파일이 늘어난다
- 3.4 순위 기록 — 저장 위치가 localStorage에서 서버 DB로
- 4.1 알려진 제약 — 실행 환경과 배포처가 바뀐다
- 8. 2차 구현 예정 — 예정이던 것이 현재형이 된다

## 새로 넣을 절

- 인증과 역할 — 선생님과 학생 둘, 반 단위는 없다
- 데이터 모델 — 사용자, 문항, 응시 기록
- 권한 — 누가 무엇을 읽고 쓸 수 있는가
- 문항 생성 — 선생님이 화면에서 요청하고 서버가 Anthropic API를 호출한다
- 비밀값 관리 — anon 키와 service_role 키를 어디에 두는가

## 고치지 말 것

- 3.6절의 문제 데이터 작성 규칙 여덟 가지와 확인 수단 표
- 2절 게임 규칙, 3.1~3.3, 3.5의 화면 동작
- 4.3 접근성
- 부록

이미 구현되어 검증까지 끝난 것이라 2차에서 바꾸기로 한 자리가 아니면
건드리지 않는다.

## 절차

1. 고치기 전에 spec/PRD.md를 archive/PRD-v5.md로 저장한다.
   첫머리에 어느 시점의 판인지와 현재 문서가 어디인지를 주석으로 적는다.
2. 고칠 절과 새로 넣을 절의 목록을 먼저 보이고 확인을 받는다.
3. 확인을 받은 뒤에 고친다.

**확인을 받을 수 없으면** 목록을 보고서 맨 앞에 그대로 싣고, 확인 없이
진행했다는 것을 첫 줄에 적는다. 목록을 만드는 일 자체를 건너뛰지 않는다.
잘못 읽은 것을 잡는 자리가 그 목록이기 때문이다.

## 멈출 조건

55번에 결정이 적혀 있지 않은 것을 만나면 추측하지 말고 묻는다.
특히 이런 것들이다.

- 문항을 DB에 둘지 파일에 둘지
- 2차 개발 단계를 몇 개로 나눌지
- 화면이 몇 개가 되는지

규격 문서에 근거 없는 문장이 들어가면, 나중에 그 문장을 근거로 또 다른
결정을 하게 된다.

**멈춘다는 것은 그 절만 비워 두고 나머지를 계속한다는 뜻이다.** 전체를
세우지 않는다. 비워 둔 절과 왜 비웠는지를 보고에 적는다.

## 어긋난 자리를 찾는 방법

**저장 위치나 실행 위치를 바꾸면 그것을 서술한 모든 자리가 따라 움직인다.**
고칠 절만 고치고 끝내지 않는다.

- **고치기 전에 검색해 목록을 만든다.** 고친 뒤에 검색하면 이미 바꾼 자리가
  안 걸려 목록 자체가 불완전해진다
- **문구가 아니라 식별자로 찾는다.** localStorage, questions.js, GitHub Pages
  같은 이름과 "4.1절 3번" 같은 절 참조가 식별자다
- **spec/ 전체를 본다.** PRD만이 아니라 IMPL-PLAN.md의 검증 절차와
  체크리스트도 같은 자리다
- **절 번호가 바뀌면 그 번호를 가리키는 자리를 전부 찾는다.** 항목을 지우거나
  더하면 뒤 번호가 밀린다

## 보고

- 어느 절을 어떻게 고쳤는지 절 번호로 적는다
- **검색에 무엇을 썼는지 그대로 적는다.** 다음 사람이 같은 검색을 돌릴 수 있게 한다
- 새로 넣은 절의 제목과 요지를 적는다
- 묻기로 한 것을 목록으로 낸다
- 55번에 있는데 반영하지 못한 것이 있으면 그것도 적는다
```

## 이 프롬프트가 왜 이런 모양인가

| 부분 | 까닭 |
|---|---|
| 근거 문서를 가리킴 | 대화 기억에 기대면 세션이 바뀔 때 재현되지 않는다 |
| 고칠 절을 번호로 지정 | "2차에 맞게 고쳐 줘"만 주면 어디까지 손댈지가 매번 달라진다 |
| 고치지 말 것을 따로 적음 | 규격 동결이 끝났다고 해서 전부 열린 것이 아니다 |
| 보존을 1번에 둠 | 고친 뒤에 뜨면 이미 늦다 |
| 목록을 먼저 보이게 함 | 잘못 읽은 것은 고친 뒤보다 고치기 전에 잡는 편이 싸다 |
| 멈출 조건을 적음 | 추측으로 채운 문장이 나중에 다른 결정의 근거가 된다 |
| 근거 문서를 고치지 못하게 함 | 근거를 고치면서 그 근거로 규격을 고치면 대조해도 어긋난 자리가 안 보인다 |
| 확인을 못 받을 때의 지침을 둠 | 없으면 절차를 통째로 건너뛰게 된다 |
| 멈춤이 무엇을 뜻하는지 밝힘 | "묻는다"와 "물을 것을 목록으로 낸다"가 서로 다른 것을 시켰다 |
| 찾는 방법을 적음 | 어긋난 자리의 목록을 적으면 다음 개정에서는 다른 목록이 나온다 |

**뒤의 넷은 [57번](../../history/impl_v2/57-prd-phase2-review.md) 검토를 받아 더한 것이다.** 처음 판으로 실행했을 때 근거 문서가 같은 커밋에서 고쳐졌고, 확인 절차가 건너뛰어졌고, 계획서의 참조 둘이 끊긴 채로 남았다.
