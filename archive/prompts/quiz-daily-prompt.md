# 통합 명령어 작성을 위한 프롬프트

## 만들 것

- 위치는 `.claude/commands/quiz-daily.md`.
- 인수로 카테고리와 문항 수를 받아줘. 둘 다 생략할 수 있다.

## 먼저 읽을 것

- `.claude/commands/quiz-add.md`
- `.claude/commands/quiz-validate.md`
- `.claude/commands/quiz-stats.md`
- `spec/IMPL-PLAN.md`

## 밟을 순서

1. `/quiz-add`로 문항을 넣는다.
2. `/quiz-validate`를 **다른 세션에 요청한다.** 직접 부르지 않는다.
3. `/quiz-stats`로 분포를 센다.

## 강제할 것

- **세 절차를 차례로 밟되 각각 따로 부를 것.** 무엇을 불렀는지와 각각의 결과를 따로 적는다.
  앞 절차가 뒤 절차의 결과를 이미 보였더라도 묶지 말라.
- 잇는 방법은 **본문에 순서를 자연어로 적는 것**이다. `&&`를 쓰지 말라.
  클로드 코드에서 `&&`는 뒤엣것을 앞 명령어의 인수 문자열로 만든다.
- **검증은 문항을 쓴 세션이 하지 않는다.** 그 까닭은 규격에 있다.
  다른 세션에 요청만 하고 **회신을 기다리지 않는다.** 요청한 사실을 보고에 적고
  회신이 오면 그때 알린다.
- 부를 세션이 없으면 직접 돌리되 **하루치 점검이고 규격이 정한 닫는 판정이 아니라는 것**을
  보고에 적을 것.
- 인수 읽는 방법은 `/quiz-add`가 정한 것을 그대로 쓸 것.
- 인수를 절차마다 나눠 넘길 것. 문항 수는 추가에만 쓰이고 카테고리는 셋 다에 쓰인다.
- 문항 수가 0이면 추가를 건너뛰고 검증 요청과 분포만 돌 것.
- 넣을 문항이 스물을 넘으면 넣기 전에 알리고 확인을 받을 것.
- 앞 절차가 걸리면 멈추고 무엇이 걸렸는지 적을 것. 걸린 채로 다음으로 넘어가지 말라.
- 마지막에 결과를 한자리에 모으되 **검증 칸은 회신 전까지 "요청함, 회신 대기"로 둘 것.**

## 금지할 것

- 세 절차의 기준을 이 파일에 베껴 적지 말라. 각 명령어 파일을 가리키게 하라.
- 절차를 새로 만들지 말라. 셋은 이미 있다.
- 검증 결과를 기다리느라 세 번째 절차를 미루지 말라.
