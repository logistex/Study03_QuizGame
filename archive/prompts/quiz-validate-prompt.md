# 문제 검증 명령어 작성을 위한 프롬프트

## 만들 것

- 위치는 `.claude/commands/quiz-validate.md`.
- 인수로 카테고리를 받고, 생략하면 전체를 검증하게 해줘.

## 먼저 읽을 것

- `spec/PRD.md`
- `spec/IMPL-PLAN.md`
- `history/12-question-guidelines.md`

절 번호는 내가 지정하지 않으니 문서에서 직접 찾으라.

## 강제할 것

- 자동으로 포착되는 것과 사람이 확인해야 하는 것을 분류하여 각각의 실행 단계를 명령어에 적을 것.
  분류 근거도 규격에 있다.
- 사람이 확인하는 항목은 **빠짐없이** 모아 표로 만들고, 행마다 근거 절을 적을 것.
- 추가로 수행할 항목은 각각이 규격에 있는지 없는지를 **네가 규격을 읽고 판정**할 것.
  있으면 근거 절을, 없으면 "규격 밖"을 표시할 것.
- 보고에서 자동 검사 결과와 사람의 판단을 구분하여 적을 것.
- 규격과 코드가 어긋난 것은 `id`가 없으니 문항 지적과 별도로 모아 "규격에 반영할 것"으로 적을 것.
- 검증에서 문제가 확인된 것이 없으면 "고칠 것 없음"이라고 적을 것. 이것도 점검 결과다.

## 금지할 것

- 검증 기준을 새로 만들지 말라. 규격에 이미 있다.
- 내 말을 그대로 믿지 말라. 그 항목이 규격에 있는지 없는지는 규격을 열어서 판정하라.
- 문제 파일을 수정하지 말라. 수정 여부는 내가 정한다.

## 추가로 수행할 것

- 해설의 연도, 수치, 인명은 외부 출처 두 곳 이상으로 대조할 것.
  기억에 의한 판정은 금지한다. 출처가 갈리면 갈린 대로 적고, 확인하지 못하면 "미확인"으로 적을 것.
- 이미 대조가 끝난 문항은 다시 대조하지 말고,
  어느 문서 어느 절에서 확인했는지와 그 기록이 어느 시점 판본을 본 것인지 적을 것.
- 외부 출처 대조를 실제로 수행하는 문항이 20개를 넘으면 분할하여 병렬로 확인하고,
  각 묶음은 결과를 파일로 먼저 기록할 것. 20개 이하면 분할하지 말 것.

## 보고 형식

검증에서 문제가 확인된 것은 `id`, 무엇이 어긋나는지, 권고 문구 순으로 적는다.
