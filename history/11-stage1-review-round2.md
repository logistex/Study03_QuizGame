## 1. 반영 검증

반영본으로 같은 값을 다시 넣었다.

| 넣은 값 | 결과 |
|---|---|
| `options[1] = ''` | `kh_01: options[1]가 비어 있음` |
| `options[1] = 123` | `kh_01: options[1]가 비어 있음` |
| `options[1] = options[2] = undefined` | 빈 값 2건 + `중복된 선택지 'undefined'` |
| `id` 삭제 1문항 | `korean_history[0]: id가 비어 있음` |
| `id` 삭제 2문항 | 두 문항 각각 `id가 비어 있음` |
| 선택지 중복(정상 값) | `중복된 선택지 '이성계'` — 회귀 없음 |
| 정상 데이터 | `[]` |

- 빈틈 4건이 모두 막혔다
- `id` 누락이 `id 중복`으로 보고되던 것이 사라졌다
- `undefined` 중복은 세 갈래로 잡힌다. 조치 3이 조치 2를 이중으로 받친다

- 앞 문장("`CATEGORIES`에 없는 키는 검사되지 않는다")만 맞고 뒤 문장이 사실과 다르다. 정정을 그대로 받는다
- 조치 없음에 동의한다

## 3. 미반영 조치 5 — 결론은 수용, 근거는 바꾸기를 권한다

결론에 이견이 없다. 길이 검사를 지금 넣을 필요는 없다. 다만 든 근거가 세 조치를 가르지 못한다.

- 회신은 "PRD 4.2절 검사 아홉 항목 밖"을 이유로 들었다
- PRD 4.2절 원문을 확인한 결과, 반영한 두 건도 아홉 항목 밖이다

| 조치 | PRD 4.2절 해당 항목 | 밖인가 |
|---|---|---|
| 1. `id` 존재 검사 | "`id`가 **중복되지 않는가**" — 존재는 없다 | 밖 |
| 3. 선택지 원소 검사 | "**`question`, `explanation`**이 비어 있지 않은가" — `options`는 없다 | 밖 |
| 5. 길이 검사 | 없다 | 밖 |

- 셋 다 밖이므로 "밖이라서 안 넣는다"는 조치 5만 빼는 근거가 되지 못한다
- 실제로 셋을 가르는 것은 PRD 4.2절 표의 두 번째 열, "빠뜨릴 때 증상"이다

| 조치 | 빠뜨릴 때 증상 |
|---|---|
| 1 | 3단계 R2 검증이 예외로 죽는다 |
| 3 | 빈 버튼이 그려지고 피드백이 "정답은 입니다."가 된다 |
| 5 | 없다. PRD 4.3절이 이미 "글이 길면 줄바꿈해 전부 보이게 한다"고 요구한다 |

- 같은 결론에 이르되, 다음에 비슷한 판단이 왔을 때도 갈리지 않는 기준이다
- 권고 문구: "아홉 항목 밖이라서"가 아니라 "빠뜨려도 증상이 없고 PRD 4.3절이 이미 흡수하므로"

## 4. 파생 — PRD 4.2절에 두 줄을 더할 것

회신이 걱정한 어긋남이 조치 1과 3을 넣는 순간 이미 일어났다.

> 규격에 없는 검사가 늘어나는 쪽으로 흐른다. 검사 함수가 무엇을 보증하는지가 PRD와 어긋나기 시작한다

- 지금 코드는 PRD 4.2절보다 두 항목 앞서 있다
- 두 검사는 넣는 것이 맞았다. 되돌릴 일이 아니다. 규격 쪽을 맞춰야 한다
- PRD 4.2절 표에 두 줄을 더하기를 권한다

| 검사 | 빠뜨릴 때 증상 |
|---|---|
| `id`가 비어 있지 않은가 | 3단계 R2 검증이 원본을 못 찾아 예외가 난다 |
| 선택지 원소가 비어 있지 않은 문자열인가 | 빈 버튼이 그려지고 오답 피드백이 "정답은 입니다."가 된다 |

- 이러면 조치 5를 뺀 근거도 표 안에서 자명해진다. 증상 열이 빈 항목은 넣지 않는다
- 2차 문제 확대 때 길이 검사를 넣겠다는 계획에는 동의한다. 그때는 사람 눈으로 재기 어려워져 증상이 생긴다
