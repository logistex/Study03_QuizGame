## 2. 완료 기준 확인

일곱 절차 모두 통과했다. 1번은 실제로 한 판을 풀었고, 나머지는 계획서가 허용한 대로 콘솔에서 저장 함수를 직접 불렀다.

| # | 확인 | 결과 |
|---|---|---|
| 1 | 한 판을 끝까지 풀기 | 결과 화면에 `0 / 10 정답`, `정답률 0%`, `홍길동 — 한국사 도전`, `순위표 1위 진입`. 한국사 표에 한 줄, 그 줄이 강조 |
| 2 | 저장값 확인 | 다섯 키가 모두 있고 `korean_history`에 `{name, score, total, date}` 한 건. `date`가 `2026-08-16`으로 오늘 |
| 3 | 다시 도전 | 이름을 다시 묻지 않고 `홍길동`으로 새 판. 문제 구성이 1번과 다름 |
| 4 | 낮은 점수 판 | 아래 줄로 가고 강조된 줄이 정확히 하나 |

| 6 | 6판 쌓기 | 반환값이 `0, 1, 2, 3, 4, null`. 5줄만 남고 가장 낮은 4점이 사라짐. 6번째는 미진입 |
| 7 | 기록 지우기 | 확인창 뒤 다섯 표가 모두 빈 문구. 저장 키가 사라짐 |

전 범위 표는 12건을 넣어 10줄로 잘리는 것을 따로 확인했다.

## 3. 위험 구간 확인

### R3 — 인덱스를 객체 참조로 찾기

계획서대로 **코드 확인이 유일한 수단**이다. 화면으로는 판정되지 않는다.

```
grep -nE 'findIndex|\.name ===' script.js
  92: q.options.findIndex(...)        1단계 선택지 중복 검사
 440: typeof item.name === 'string'   sanitizeList의 형태 검사
```

`saveRanking` 안에 이름 비교가 없고, `data[key].indexOf(record)`를 쓴다.

실행으로 판정되는 두 항목도 함께 봤다.

- **같은 이름 기록을 합치지 않는다** — 같은 이름, 같은 점수를 두 번 넣으니 두 줄이 각각 남았다. 반환값은 둘 다 `0`이다. 맨 앞 삽입에 안정 정렬이라 나중 기록이 위로 온 것이고, 계약대로다
- **강조는 `highlightIndex`로만 건다** — 같은 이름 두 줄에서 강조가 하나뿐이고 위쪽 줄이었다. 이름 대조로 클래스를 걸었다면 두 줄이 모두 강조됐을 자리다

### R4 — `toISOString` 금지

- `grep -n 'toISOString' script.js`는 주석 한 줄만 잡는다. 코드에는 없다
- `formatDate(new Date('2026-08-12T01:30:00+09:00'))`가 `'2026-08-12'`를 돌려준다. UTC 기준이면 `'2026-08-11'`이 나왔을 자리다

## 4. 나머지 체크리스트

| 항목 | 결과 |
|---|---|
| 정렬 비교 함수가 `(a, b) => b.score - a.score` 한 줄 | 그렇다. 동점 처리를 넣지 않았다 |
| 저장 함수가 쓰기 직전에 읽는다 | `saveRanking` 첫 줄이 `readRankings()`다. 화면 진입 때 읽어 둔 변수를 쓰지 않는다 |
| 카테고리 5줄, 전 범위 10줄 | 그렇다 |
| 결과 화면에 해당 모드 표 하나만 | `#result-ranking`에 표가 하나, 그룹이 0이다 |
| 순위 번호가 줄 순서대로 | 동점 두 줄이 1, 2로 매겨진다 |
| 이름이 `textContent` | 이름을 `<b>홍</b>`으로 넣으니 `<b>` 요소가 0개, 글자 그대로 보인다 |
| 저장값 전체 손상 | `{{{`로 깨뜨리면 다섯 표가 빈 배열로 복구되고 게임이 진행된다 |
| 한 표만 손상 | `korean_history`만 문자열로 바꾸니 한국사만 비고 과학 기록은 남았다 |
| 저장 불가 경로 | `setItem`이 던지게 만들고 만점으로 끝내니, 진입 문구가 비고 순위표가 감춰지고 안내만 남았다. `순위표에 들지 못했습니다.`가 뜨지 않는다 |

마지막 항목이 검토 1차에서 지적됐던 자리다. 만점자에게 미진입 문구가 뜨는 것을 막는 것이 `'unavailable'`을 따로 둔 이유였다.

## 5. 계획과 다르게 한 것

**"다시 도전"에서 이름을 되돌려 넣는다.**

계획서는 "같은 모드, 같은 카테고리로 `startGame`을 다시 부른다. 이름은 직전 판의 이름을 그대로 쓴다"고 적었다. 그런데 `startGame`은 첫 줄에서 `readPlayerName()`으로 입력란을 읽는다. 결과 화면에서 부르면 입력란 값에 따라 판이 달라진다.

```javascript
document.getElementById('player-name').value = state.playerName;
startGame(state.mode, state.categoryId);
```

- `startGame`의 함수 계약을 바꾸지 않으려고 입력란을 직전 판의 이름으로 되돌린 뒤 부른다
- 시작 화면으로 돌아가도 그 이름이 남아 있어 "처음으로"의 동작과도 어긋나지 않는다
- 계약에 인자를 더하는 쪽이 깔끔하지만, 2단계에서 확정된 함수를 4단계에서 고치는 일이라 택하지 않았다

그 밖에 계획과 다르게 한 것은 없다.
