개정이 두 번으로 나뉘지만, 5단계 검증이 어긋난 채 도는 것보다 낫다.

## 3. 현행 체계와 대조

| 가이드라인 | 현행 | 판정 |
|---|---|---|
| 1. 정답 유일성 | `IMPL-PLAN.md` 1.8절 육안 검토 4번에 있음 | 있으나 **자리가 틀림** |
| 2. 최상급 기준 | 규칙 없음 | 공백 |

| 4. 교차 검증 | 절차 없음 | **가장 큰 공백** |

### 1번은 자리가 틀렸다

- "정답이 둘로 읽히지 않는가"가 계획서 1.8절 **완료 기준**에만 있고 PRD 3.6절 **작성 규칙**에는 없다
- 문제를 쓰는 사람은 3.6절을 보지 1.8절을 보지 않는다
- 검증에서 걸러내는 것보다 쓸 때 안 만드는 편이 싸다

### 4번이 왜 가장 큰 공백인가

현재 흐름은 이렇다.

```
작성자 지식 → 작성자 육안 검토 → 검토자 지식
```

- 두 단계 모두 기억에 의존한다. 검토 측도 40문항을 지식으로 대조했지 출처를 확인하지 않았다
- 작성자와 검토자가 같은 오해를 공유하면 그대로 통과한다

실제로 **자료에 따라 서술이 갈리는 문항이 다섯 개** 있다.

| 문항 | 우리가 고른 것 | 다른 서술 |
|---|---|---|
| `kh_07` | 1610년 완성 | 1613년 간행 |
| `kh_09` | 1485년 시행 | 반포, 완성 시점이 자료마다 다름 |
| `ac_10` | 1876년 작곡 | 1877년 초연 |
| `ge_02` | 8,849m | 8,848m (2020년 재측량 이전) |
| `sc_10` | 왓슨과 크릭 | 프랭클린 기여 논란 |

- 다섯 다 **우리가 고른 쪽이 맞다.** 문제는 어느 근거로 골랐는지가 남아 있지 않다는 것이다
- 나중에 "1613년 아닌가"라는 지적이 오면 처음부터 다시 판단해야 한다
- 가이드라인 4번의 "논란 있는 내용은 주류 학설 기준"을 `sc_10`, `ge_02`에서 이미 적용했는데 그 판단이 문서에 없다

### 실측 — 40문항의 노출 지점

최상급 표현 9곳을 확인했다. 기준이 문항에 명시된 것은 셋뿐이다.

| 상태 | 문항 |
|---|---|
| 문항에 기준 명시 | `ge_09`("국토 면적이"), `ge_06`, `ge_07`("더운" 사막) |
| 해설에서 보완 | `sc_03`(지름), `ge_01`(면적) |
| 암묵 | `sc_05`, `sc_06`, `ge_02`, `ge_04` |

- 가장 걸리는 것은 **`ge_02` "세계에서 가장 높은 산"** 이다. 해발이면 에베레스트, 산 기저부터면 마우나케아, 지구 중심에서 멀기로는 침보라소다
- 교과 수준에서는 논란이 아니므로 **지금 고칠 필요는 없다**
- `ge_09`가 본보기다. "국토 면적이 세계에서 가장 넓은 나라"처럼 기준을 문항에 넣으면 해석이 갈리지 않는다

시점 의존 서술은 둘이다.

- `ge_02` 8,849m — 2020년 공동 재측량치. 이전 자료는 8,848m라 교과서에 따라 다르다
- `ac_01` "지금은 루브르 박물관에 있다" — 표현 자체가 시점 의존을 인정한다. 실무 위험은 낮다

나머지 수치 28건은 역사적 상수라 안전하다.

## 4. 자리 배정 — 산출물 속성인가 작업 절차인가

넷을 가르는 기준은 **완성된 데이터만 보고 판정되는가**다.

| 항목 | 데이터만 보고 판정 가능한가 | 자리 |
|---|---|---|
| 1. 정답 유일성 | 문항만 보면 판정된다 | PRD 3.6절 |
| 2. 최상급 기준 | 문항만 보면 판정된다 | PRD 3.6절 |
| 3. 시점 명시 | 문항만 보면 판정된다 | PRD 3.6절 |
| 4. 교차 검증 | **불가능하다.** 출처를 둘 봤는지는 결과물에 흔적이 없다 | `IMPL-PLAN.md` 1.8절 |

- 1~3은 데이터가 만족해야 할 조건이고 4는 작업자가 거쳐야 할 절차다. 전자는 명세, 후자는 공정이다
- PRD 3.6절에는 이미 같은 성격의 규칙 여섯 개가 있다. 특히 "선택지의 위치를 지칭하는 표현을 쓰지 않는다"는 1~3과 완전히 같은 종류다. 자동 검사는 불가능하고, 사람이 문항을 보면 판정되며, 어기면 데이터가 못 쓰게 된다
- 4는 PRD에 넣을 수 없다. PRD는 산출물을 규정하는데 "출처를 둘 이상 봤는가"는 산출물의 속성이 아니다

### 검사 함수에는 넣지 않는다

- 넷 다 사람 판단이라 통과, 차단으로 만들 수 없다
- 앞서 합의한 "빠뜨릴 때 증상이 있는 것만 검사에 넣는다"는 기준에도 맞지 않는다
- 다만 **최상급 표현이 든 문항 목록을 뽑아 주는 보조 스크립트**는 값어치가 있다. 판정은 사람이 하되 어디를 볼지 알려 주는 용도다. 3절의 실측이 그 형태다

## 5. 가이드라인에 없지만 필요한 것 — 문항 간 중복

- 받은 가이드라인 넷은 전부 **문항 하나 안**을 본다. 문항 사이를 보는 장치가 없다
- 검사 함수는 `question` **텍스트** 중복만 잡는다
- "조선을 건국한 인물은?"과 "1392년 조선을 세운 사람은?"은 텍스트가 달라 통과하지만 같은 문항이다
- 40문항에서는 나오지 않았으나 **2차 확대 때 반드시 나온다.** 카테고리마다 문항을 늘리다 보면 같은 사실을 다른 문장으로 묻게 된다
- 4번과 함께 `IMPL-PLAN.md` 1.8절에 넣는다

## 6. 미룬 항목의 실행 시점 — 8절에 못박을 것

**11번의 권고에 구멍이 있었다.** PRD 보완을 "2차 착수 직전"으로 미뤘는데

- 6단계가 끝나면 1차가 완료되고 배포된다
- PRD 8절은 "2차 구현 예정"일 뿐 착수 시점이 없다
- 따라서 실행 시점이 없는 약속이 된다

이 프로젝트의 작업 지침이 정확히 이 경우를 경고한다.

> 의도적으로 미룬 검증은 문서에 메모만 남기지 말고, 추적 가능한 후속 작업으로 명시한다 — 그렇지 않으면 병합되는 순간 조용히 "완료"로 취급되기 쉽다

**PRD 8절에 선행 조건 문단을 넣기를 권한다.** "예정" 목록 옆의 메모가 아니라, 2차를 시작하려는 사람이 반드시 밟는 관문이어야 한다.

> 2차에 착수하기 전에 다음을 먼저 반영한다. 문항이 늘어나면 사람 눈으로 걸러 내기 어려워지는 것들이다.
>
> - 3.6절에 정답 유일성, 최상급 기준 명시, 시점 의존 수치 회피를 더한다
> - 6절 1단계의 육안 검토에 출처 교차 확인과 문항 간 중복 확인을 더한다

- 8절은 이미 "문제 추가는 3.6절의 작성 규칙과 4.2절의 데이터 검사를 통과해야 한다"고 적고 있다. 그 옆에 "그 규칙을 먼저 이렇게 보강한다"를 두면 읽는 순서가 자연스럽다

## 7. CLAUDE.md에 대한 판단

프로젝트 수준 `CLAUDE.md`에 이 규칙들을 넣는 방안을 검토했다.

**규칙 본문은 넣지 않기를 권한다.**

- PRD, 계획서, `CLAUDE.md` 세 곳에 규칙이 흩어지면 이 프로젝트가 세 라운드에 걸쳐 해결한 "어느 문서가 기준인가" 문제가 재발한다
- 지금 넣으려는 넷 중 PRD나 계획서에 자연스러운 자리가 없는 항목이 하나도 없다
- `CLAUDE.md`는 다른 곳에 갈 자리가 없을 때 만드는 것이 맞다

**다만 자동 로드의 이점은 실재한다.** 2차 확대 때 문제를 쓰는 세션이 PRD 3.6절을 찾아보지 않을 위험이 있다. 절충안으로 포인터 한 줄만 둔다.

```
문제 데이터를 쓰거나 고칠 때는 spec/PRD.md 3.6절의 작성 규칙을 먼저 읽는다.
```

- 규칙이 바뀌어도 고칠 곳은 PRD 한 곳이다

**`CLAUDE.md`가 실제로 필요한 것은 따로 있다 — 저장소 구조 규칙이다.**

- `history/`는 번호순, `spec/`은 명세, `archive/`는 보존판, 코드 넷은 배포 때문에 루트
- 이건 PRD에도 계획서에도 자리가 없다. 지금은 `09-repo-reorg.md`에만 있는데 기록 문서라 다음 세션이 자동으로 읽지 않는다
- 새 문서를 어디에 둘지 매번 판단하게 되므로, `CLAUDE.md`를 만든다면 이쪽이 본체다
