## 4. 지켜야 할 규칙

### 규격 동결

**2단계부터 6단계까지 PRD를 고치지 않는다.** 규격 변경이 필요하면 PRD 8절(2차 구현 예정)로 보낸다.

예외는 하나다. **코드와 규격이 어긋난 것을 발견했을 때.** 새 요구를 넣는 것이 아니라 이미 구현된 것을 적는 일이라 설계를 흔들지 않는다.

계획서도 같은 기준을 쓴다. 남은 단계의 함수 계약과 요소 id 계약은 건드리지 않는다. 다만 이미 끝난 단계의 검증 절차를 고치는 것은 된다. 계획서는 "어떻게 확인하는가"라 산출물이 바뀌지 않기 때문이다.

### 단계마다 하는 일

1. 챕터 표시를 남긴다. **일이 실제로 시작될 때** 찍는다. 미리 찍으면 엉뚱한 작업이 그 아래 들어간다
2. 계획서의 해당 단계 절을 읽고 그대로 구현한다
3. 완료 기준과 체크리스트를 하나씩 밟는다
4. 커밋하고 태그를 붙인다 — `git tag stage4 && git push origin --tags`
5. 작업 보고서를 `history/`에 쓴다
6. 노트용 요약을 만들어 노션에 넣는다
7. README의 단계 표와 문서 목록을 갱신한다

검토 지적을 반영할 때는 하나가 더 붙는다.

8. **코드, 계획서, PRD 셋을 한 번에 맞추고 그 사실을 알린다.** 4단계에서 코드와 계획서만 고치고 PRD를 빼놓아, 두 규격 문서가 서로 다른 동작을 가리키는 채로 회신을 보냈다(26번). 회신을 쓴 뒤에 결정이 더 나오면 회신 문서에 덧붙임을 남긴다

### 문서 작성

- 요약문은 **개조식**으로 쓴다. 마침표를 붙이지 않고 굵게 표기도 쓰지 않는다. 20~30줄로 짧게
- 설명이 필요한 낱말을 쓰지 않는다. "탐침", "산문" 같은 표현으로 두 번 지적받았다
- 가운뎃점 대신 쉼표를 쓴다
- 새로 만드는 파일 첫머리에 `<!-- 생성: YYYY-MM-DD HH:MM KST -->`를 넣는다. 시각은 `TZ=Asia/Seoul date`로 확인한다

## 5. 작업 환경

### 미리보기 서버

`.claude/`에 `serve.py`와 `launch.json`이 있다. 둘 다 gitignore 대상이라 새 세션에는 없다. **없으면 아래 파일을 다시 만들고 `launch.json`이 이것을 띄우게 한다.**

```python
# .claude/serve.py
import http.server


class NoCacheHandler(http.server.SimpleHTTPRequestHandler):
    def end_headers(self):
        self.send_header('Cache-Control', 'no-store')
        super().end_headers()


if __name__ == '__main__':
    http.server.test(HandlerClass=NoCacheHandler, port=8010, bind='127.0.0.1')
```

**브라우저가 `script.js`를 캐시해 새 코드가 실행되지 않는 일이 3단계까지 매번 생겼다.** 원인은 `python3 -m http.server`가 `Cache-Control`을 보내지 않고 `Last-Modified`만 보내는 것이다. 그래서 브라우저가 신선도를 스스로 추정해 캐싱한다. 강제 새로고침과 새 탭으로는 안 풀렸고 포트를 바꾸는 것만 통했는데, 새 오리진에 캐시 항목이 없어서였다.

`no-store`를 붙이면 원인 자리에서 막힌다. **포트를 바꿔 가며 개발하지 않는다.** 포트가 바뀌면 오리진이 달라져 `localStorage`가 분리되고, 4단계부터는 순위 기록이 사라진 것처럼 보인다.

포트는 **8010**이다. PRD 4.1절은 8000으로 적었으나 다른 작업이 그 포트를 쓰고 있어 비켜 두었다. 8000이 비면 되돌려도 된다. 중요한 것은 값이 아니라 **고정**이다.

### 노션 노트

- 페이지: `5장. 체계적인 개발과 관리 (퀴즈 게임 앱) 데스크톱 버전`
- 페이지 id: `3b8022e2-cfe7-8087-886a-c13e7272d221`
- 구조: `5.1.6.N`이 각 구현 단계, 그 아래 `a)`, `b)`, `c)`로 주고받은 문서

편집 규칙이 있다. 세 번 사고를 내고 얻은 것이다.

1. **넣기 전에 그 자리 원문을 탭까지 그대로 확인한다.** 노션 본문은 탭으로 들여쓰고 공백이 아니다
2. **붙일 자리의 앞뒤를 포함한 유일한 문자열**을 `old_str`로 잡는다
3. **넣은 뒤 이웃 블록이 그대로인지 확인한다.** 이것을 빠뜨려 블록 하나를 잃은 적이 있다
4. 한글을 유니코드 코드값으로 적다 오타를 네 번 냈다. 넣은 뒤 반드시 되읽는다

토글 블록은 만들 수 있다. `<details>` / `<summary>`이고 자식을 탭으로 들여쓴다. 계층은 `5.1.6.N`이 탭 2개, `a)`가 3개, 그 아래가 4개, 항목이 5개다.

## 6. 도구의 한계

**브라우저 자동화가 키 이벤트의 기본 동작을 일으키지 못한다.** `keydown:Enter`는 페이지에 도착하는데 클릭이 합성되지 않는다. 그래서 초점 이동까지만 자동으로 확인하고 **누르는 것은 사람에게 맡긴다.** 2단계에서 이 방식으로 항목을 닫았다.

`confirm`으로 뜨는 브라우저 확인창도 자동으로 띄울 수 없다. 대신 핸들러가 붙어 있는지를 세어 판정했다.
