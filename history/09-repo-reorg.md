## 1. 움직일 수 없는 것

- **코드 네 개는 루트에 둔다.** GitHub Pages는 브랜치 배포에서 루트나 `/docs`만 소스로 잡는다. 하위로 내리면 배포 경로가 바뀌고 PRD 1.4절과 어긋난다
- **`README.md`도 루트에 둔다.** 저장소 첫 화면이다
- **`docs/`라는 폴더 이름은 쓰지 않는다.** Pages 배포 소스로 오인되고, gitignore된 `doc/`와 한 글자 차이다
- **`doc/`, `PRD 검토 가상본`은 손대지 않는다.** gitignore 대상이다
- **작업 폴더 이름은 바꾸지 않는다.** 클라우드 동기화 경로이고, 로컬 서버로 여는 방식이면 공백, 한글 문제는 이미 우회된다

## 6. 뒤따르는 수정

### 6.1 저장소 안의 링크

- 마크다운 링크 42곳. `README.md` 12곳이 가장 많다
- `archive/` 안에서 서로 가리키는 링크는 같은 폴더라 **그대로 유지**된다. 루트를 가리키는 것만 `../`를 붙인다
- 원칙: **링크 경로는 고치고, 본문 서술의 파일명은 손대지 않는다**
  - 검토 문서의 "PRD-v3.md는 수정본이다" 같은 서술은 그때의 논의 기록이다. 이름을 바꾸면 기록이 어긋난다

## 7. 실행 순서

1. **작업 트리를 깨끗이 한다.** 미추적 문서 4개의 처리를 먼저 정한다(9절 1번)
2. `git mv`로 옮기고 개명한다. 이력이 유지된다
3. `chmod 644`로 권한을 맞춘다
4. 저장소 안의 링크를 고친다. `README.md` → `archive/README-v*.md` → 나머지 순서
5. 링크 점검: `grep -roE '\]\([^)]+\.md\)' --include='*.md' .`로 뽑아 실제 파일 존재를 확인한다
6. 커밋하고 푸시한다. 이동과 링크 수정을 **한 커밋**에 담아 중간 상태에서 링크가 깨진 채로 남지 않게 한다
7. 승인을 받아 노션 링크 11곳을 고친다
8. 이 문서(`REORG-PLAN.md`)를 지운다. 실행이 끝나면 역할이 끝난다

## 8. 함께 처리할 잔여 작업

정리와 별개로 밀려 있는 것이다. 순서상 **정리를 먼저 하고 그 위에서 고치는 편**이 링크 수정이 겹치지 않는다.

1단계 검토 의견서(`08-stage1-review.md`)의 조치 7건 중:

| # | 내용 | 등급 | 판단 |
|---|---|---|---|
| 1 | `id` 존재, 형식 검사 추가 | 필수 | 반영 |
| 2 | 선택지 중복 판정을 `find` → `findIndex` | 필수 | 반영 |
| 3 | 선택지 원소가 비어 있지 않은 문자열인지 검사 | 권고 | 반영 (1, 2, 3번 빈틈이 함께 막힌다) |
| 4 | 계획서 1.5절을 메모리 검증 방식으로 수정 | 권고 | 반영 |
| 5 | 문항 60자, 선택지 20자 검사 추가 | 선택 | **넣지 않는다.** PRD 4.2절 아홉 항목 밖이다. 2차 문제 확대 때 PRD와 함께 정한다 |
| 6 | `sc_07`의 `림프구` 교체 | 선택 | **`혈장`으로 교체 권고.** 혈액의 네 구성 요소가 되어 층위가 맞고, 정답 인덱스는 3 그대로라 분포가 안 바뀐다 → 결정 필요 |
| 7 | 포트 표기 통일 | 선택 | 반영 (6.4절) |

검토 의견서의 지적 네 건은 직접 재현해 전부 사실임을 확인했다. 다만 **경미 1번("카테고리 키를 잘못 적으면 조용히 죽는다")은 재현되지 않았다.** 순회가 `CATEGORIES` 기준이라 키를 잘못 적으면 원래 키가 사라져 반대 방향에서 잡힌다. 조용히 죽는 것은 `CATEGORIES`에 없는 키를 추가로 넣었을 때뿐이며 무해하다. 회신에 이 정정을 담는다.

작업 보고의 "객체를 복제해 망가뜨렸다"는 서술도 부정확하다. 실제로는 복제한 문항을 **전역 `QUESTIONS`의 카테고리 배열에 넣어** 바꿨다. 지적대로 정정한다.
