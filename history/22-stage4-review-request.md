# 4단계 검토 요청

- 대상 커밋: `6c0b644`, 태그 `stage4`
- 작업 보고: [21-stage4-report.md](21-stage4-report.md)
- 근거: 20번 6절 — "4단계는 R3와 R4가 몰려 있고 R3는 실행으로 판정되지 않아 코드 확인이 유일한 수단이므로 4단계 직후 검토를 권한다"

## 1. 가장 먼저 봐 달라는 것 — R3

**이 항목은 내가 통과를 주장해도 근거가 코드 읽기 하나뿐이다.**

- 화면으로 판정되지 않는다. 맨 앞 삽입에 안정 정렬이라 이름과 점수로 찾아도 참조로 찾아도 같은 값이 나온다
- 그래서 내가 "확인했다"고 적은 것이 검증이 아니라 자기 확인이다. 1단계에서 40문제 육안 검토를 넘겼던 것과 같은 성격이다

봐 달라는 자리는 `script.js`의 `saveRanking` 하나다.

- `data[key].indexOf(record)`를 쓰는가
- 삽입한 `record`와 인덱스를 찾는 `record`가 **같은 객체**인가. 중간에 복사본이 생기면 `indexOf`가 `-1`을 돌려주고, 그러면 진입했는데도 `순위표에 들지 못했습니다.`가 뜬다
- `list.sort`가 원본 배열을 제자리에서 바꾸는데, `slice`로 자른 뒤의 배열에서 인덱스를 찾는 순서가 맞는가

## 2. 확인하지 못한 것 셋

| 항목 | 왜 못 봤나 |
|---|---|
| 두 탭 동시 저장 | 읽기를 쓰기 직전으로 미룬 것은 코드로 확인했으나, 실제 탭 두 개로 겹쳐 저장해 보지는 못했다 |

## 3. 결과보다 방법을 봐 달라는 것 둘

### 3.1 완료 기준 6번을 콘솔로 대체한 것

계획서가 허용한 방식이다. 여섯 판을 손으로 풀지 않고 `saveRanking`을 콘솔에서 여섯 번 불렀다.

- 반환값이 `0, 1, 2, 3, 4, null`로 나왔고 5줄만 남았다
- 이 방식은 `finishGame`의 경로를 건너뛴다. 완료 기준 1번이 그 경로를 덮지만 **1번은 첫 판이라 순위표가 비어 있는 상태**였고, 기록이 쌓인 상태에서 지나는 경로가 비어 있었다
- **이 빈틈은 요청서를 쓰다 발견해 메웠다.** 9점과 8점 기록을 심어 둔 뒤 실제로 한 판을 끝까지 풀었더니 `순위표 3위 진입`이 뜨고, 세 번째 줄에 들어갔으며, 강조가 하나뿐이고 그 줄이었다
- **묻고 싶은 것**: 콘솔 대체가 남기는 빈틈을 이렇게 실판 하나로 메우는 것이 맞는 방식인가. 아니면 완료 기준 자체에 "기록이 있는 상태에서 한 판"을 적어 두어야 하는가

### 3.2 저장 불가 경로를 스텁으로 검증한 것

`Storage.prototype.setItem`이 예외를 던지게 만들고 만점으로 끝내 보았다. 진입 문구가 비고 순위표가 감춰지고 안내만 남았다.

- **묻고 싶은 것**: 실제 저장 불가 상황(사파리 프라이빗 모드 등)과 이 스텁이 같은가. `setItem`만 막았고 `getItem`은 살아 있어서, `readRankings()`가 `null`이 되는 경로는 이 방법으로 확인하지 못했다

## 4. 판단을 요청하는 것 셋

### 4.1 "다시 도전"에서 입력란을 되돌리는 것

```javascript
document.getElementById('player-name').value = state.playerName;
startGame(state.mode, state.categoryId);
```

- 계획서는 "이름은 직전 판의 이름을 그대로 쓴다"고 했는데 `startGame`은 첫 줄에서 입력란을 읽는다
- 2단계에서 확정된 함수 계약에 인자를 더하지 않으려고 입력란을 되돌린 뒤 불렀다
- 계약을 지킨 대신 우회가 생겼다. `startGame(mode, categoryId, name)`으로 계약을 넓히는 쪽이 나은가

### 4.2 `sanitizeList`의 판정 단위

- 항목 하나라도 형태가 어긋나면 **그 목록 전체**를 빈 배열로 만든다. 계획서 4.1절대로다
- 다섯 개를 한꺼번에 비우지 않는 것은 맞는데, 목록 안에서 성한 항목까지 버리는 것이 옳은가. 항목 단위로 걸러 내는 쪽이 기록을 더 살린다
- 계획서를 그대로 따랐으므로 바꾼다면 계획서 수정이 함께 필요하다

### 4.3 강조 줄의 시각 표시

- 배경색과 굵은 글씨에 더해 **첫 칸 왼쪽에 4px 선**을 두었다. 색만으로 구분하지 않기 위해서다(PRD 4.3절)
- 다만 순위표는 선택지와 달리 색각 이상 관련 요구가 PRD에 명시되어 있지 않다. 과한가
