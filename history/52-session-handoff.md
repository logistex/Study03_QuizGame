## 3. 남은 일 넷

### 3.1 `/quiz-add`에 깃허브 백업을 붙인다

**노트에 적기 전에 명령어를 실제로 고친다.** 고치지 않고 적으면 노트가 없는 기능을 설명한다.

- 지금은 명령어가 `questions.js`만 고치고 커밋은 사람이 한다
- 넣은 뒤 커밋까지 하게 하면 되돌리기가 `git revert` 한 줄이 된다
- 커밋 메시지에 넣은 문항의 `id`와 출처를 적게 하면 무엇을 왜 넣었는지가 남는다
- 실습에서 git을 안 쓰는 학생은 되돌릴 방법이 없다. 백업을 절차에 넣는 까닭이다

고친 뒤 3.2를 돌리면 그 실행이 곧 백업 기능의 확인이 된다.

### 3.2 지리와 예술과 문화에 다섯씩

### 3.3 노트 5.2.7 두 절

절 제목은 사용자가 노션에 만들어 두었다. 초안은 대화에서 드렸고 여기 요지만 남긴다.

**5.2.7.1 `/quiz-add`에 깃허브 백업 붙이기** — 지금은 명령어가 파일만 고치고 커밋은 사람이 한다.
커밋이 곧 백업이므로 명령어에 커밋까지 붙이면 되돌리기가 `git revert` 한 줄이 된다.
교재는 백업을 따로 두는데 우리는 git이 그 자리다. **명령어를 고치는 것은 3.1이다.**

**5.2.7.2 카테고리별 문항 수 맞추기** — 3.2를 돌리고 결과를 적으면 된다.
전 범위 도전은 `3+3+2+2`로 고정이라 동작에는 문제가 없었으나 문항 하나가 뽑힐 확률이 카테고리마다 갈렸다.
PRD 8절이 문항 수가 갈릴 때의 규정을 안 두었다. 규격의 공백이다.

### 3.4 노트 5.3 목차와 결정 셋

사용자가 잡은 목차다.

```
5.3.1 기존 앱의 한계점
5.3.2 신규 앱에 필요한 논리적 기능
5.3.3 신규 앱의 DB 도입 필요성
5.3.4 신규 앱의 배포 방법 변경 필요성
5.3.5 기존 자산의 승계 범위
5.3.6 신규 앱의 PRD 작성
5.3.7 신규 앱의 개발계획서 작성
5.3.8 신규 앱의 구현
5.3.9 신규 앱의 검증
```

**아직 안 정한 것 셋이다.**

- 무엇으로 인증하고 무엇에 저장하는가. 학생이 따라 할 수 있어야 하니 무료 티어와 가입 절차가 판단 기준이다
- 배포를 어디로 옮기는가. GitHub Pages는 정적 호스팅이라 DB를 못 붙인다. 1차 구현물과 `gh-pages` 여섯 스냅숏은 그대로 두고 2차만 옮기는 방식이 된다
- 어디까지가 5장인가. 교재는 5장에서 정적 앱으로 끝내고 6장에서 API로 간다. 우리 5.3이 교재의 6장 자리까지 당겨 오는 셈이다

**선생님 기능이 인증 기반이라 DB와 묶여 있다.** 이름만으로는 선생님과 학생을 못 가른다.

이것들이 정해지면 PRD 1.3절, 3.4절, 4.1절, 8절을 다시 써야 한다. 2차 구현이라 PRD를 고치는 것은 되지만, 지금까지 2차에서 고친 것은 확인 수단 표 정도였고 이번은 설계를 바꾸는 일이라 규모가 다르다.
