## 2. `validateData()`

### PRD 4.2절 아홉 항목 대조

| 항목 | 구현 | 판정 |
|---|---|---|
| `CATEGORIES`의 id가 `QUESTIONS`에 있는가 | `Array.isArray(list)` | 덮음 |
| 문제 수가 `QUIZ_LENGTH` 이상인가 | `list.length < QUIZ_LENGTH` | 덮음. `>=` 의미로 정확히 썼다 |
| `options.length === 4` | 배열 여부와 길이 | 덮음 |
| `answer`가 0~3 정수 | `Number.isInteger` + 범위 | 덮음 |
| `difficulty`가 세 값 중 하나 | `DIFFICULTY_LABELS` 키 조회 | 덮음. 난이도 목록을 한 곳에만 둔 설계가 좋다 |
| `question`, `explanation` 비어 있지 않은가 | 타입과 `trim()` | 덮음 |
| 한 문제 안에 같은 선택지 | `indexOf !== index` | 덮음 (단, 아래 빈틈 3번) |
| `id` 전체 중복 | `Set` | 덮음 (단, 아래 빈틈 4번) |
| `question` 텍스트 전체 중복 | `Set` | 덮음 |

아홉 항목은 모두 덮는다. 통과만 시키고 실질을 검사하지 않는 항목은 없다.

### 실행으로 확인한 빈틈 4건

`questions.js`와 `validateData()`를 Node로 불러 정상 데이터를 하나씩 망가뜨려 확인했다. 아래는 실제 출력이다.

| # | 넣은 값 | 결과 | 왜 문제인가 |
|---|---|---|---|
| 1 | `options[1] = ''` | 검출 못 함 | 빈 버튼이 그려지고, 그 선택지가 정답이면 오답 피드백이 "정답은 입니다."가 된다 |
| 2 | `options[1] = 123` | 검출 못 함 | 선택지 원소의 타입을 보지 않는다 |
| 3 | `options[1] = options[2] = undefined` | 검출 못 함 | **중복 검사 자체의 구멍이다.** `find`가 중복 값 `undefined`를 돌려주는데 판정이 `!== undefined`라 참이 되지 않는다 |
| 4 | 한 문항의 `id` 삭제 | 검출 못 함 | `id`의 존재와 형식을 검사하지 않는다 |
| 4 | 두 문항의 `id` 삭제 | `korean_history[1]: id 중복` | **메시지가 사실과 다르다.** 중복이 아니라 누락인데 `undefined`끼리 부딪혀 중복으로 보고된다 |

**4번이 가장 중요하다.** 메시지가 오도하는 것으로 끝나지 않는다. 계획서 3단계 R2 체크리스트가 원본을 이렇게 찾는다.

```javascript
Object.values(QUESTIONS).flat().find(o => o.id === q.id)
```

`id`가 없는 문항이 섞이면 `find`가 엉뚱한 문항을 집거나 `undefined`를 돌려주고, 뒤이은 `orig.options[orig.answer]`에서 예외가 난다. **1단계 검사를 통과한 데이터가 3단계 검증을 깨뜨린다.** 검사 함수가 막아야 할 자리다.

`script.js` 45줄이 `id`가 없을 때 쓸 대체 라벨(`korean_history[1]`)을 이미 만들어 두었다. 그 경우를 예상했으면서 오류로 보고하지는 않은 셈이다.

### 고칠 곳

```javascript
// id 존재 검사를 중복 검사 앞에 둔다
if (typeof q.id !== 'string' || q.id.trim() === '') {
  errors.push(label + ': id가 비어 있음');
} else if (seenIds.has(q.id)) {
  errors.push(label + ': id 중복');
} else {
  seenIds.add(q.id);
}

// 중복 판정을 값이 아니라 인덱스로 바꾼다
const dupIndex = q.options.findIndex(function (option, index) {
  return q.options.indexOf(option) !== index;
});
if (dupIndex !== -1) {
  errors.push(label + ": options에 중복된 선택지 '" + q.options[dupIndex] + "'");
}

// 선택지 원소 검사를 더한다
q.options.forEach(function (option, index) {
  if (typeof option !== 'string' || option.trim() === '') {
    errors.push(label + ': options[' + index + ']가 비어 있음');
  }
});
```

### 경미 2건

- **`QUESTIONS`에만 있고 `CATEGORIES`에 없는 키는 검사되지 않는다.** 순회를 `CATEGORIES` 기준으로 하기 때문이다. 키를 잘못 적으면(`sciene`) 그 데이터는 조용히 죽는다. PRD가 요구한 방향은 한쪽뿐이므로 규격 위반은 아니다
- **문항 60자, 선택지 20자 제한은 검사하지 않는다.** PRD 3.6절 작성 규칙이지만 아홉 항목 밖이다. 지금 데이터는 전부 만족한다(최장 33자, 11자). 2차 문제 확대 때 넣어 두면 편하다

### 잘된 부분

- 콘솔 출력이 `{id}: {위반 내용}` 형식으로 일관되고, 위반 건수 요약 줄이 따로 있다
- `DIFFICULTY_LABELS`의 키로 난이도를 판정해 목록이 한 곳에만 있다. 화면 라벨과 검사가 갈라질 여지를 없앴다
- 전역 상수 미정의를 먼저 보고 즉시 반환한다. 그 뒤 코드가 `undefined`를 순회하지 않는다
- `init()`이 오류 시 조기 반환해 2단계 초기화 경로를 잇지 않는다. 구조가 맞다

## 3. 계획 이탈 2건에 대한 판단

### 이탈 1 — 검사 함수 검증을 브라우저 메모리에서 수행

**수용한다. 계획서 1.5절을 이 방식으로 고칠 것을 권한다.**

검증의 목적은 "검사 함수가 실제로 위반을 잡는가"이고, 그 판정에 필요한 것은 `validateData()`가 망가진 상태를 보는 것뿐이다. 파일을 고쳐 새로고침하든 메모리의 객체를 직접 고치든 함수가 보는 상태는 같다. 등가성이 성립한다.

오히려 이쪽이 낫다.

- 복구 누락 위험이 구조적으로 없다. 새로고침이 곧 복구다
- 열한 가지를 한 번에 볼 수 있다
- 파일을 건드리지 않으므로 임시 변경이 커밋에 섞일 수 없다

**다만 작업 보고의 서술은 부정확하다.** "객체를 복제해 망가뜨렸다"고 적었는데, `validateData()`는 전역 `QUESTIONS`를 직접 읽으므로 복제본을 망가뜨렸다면 함수가 그것을 볼 수 없다. 실제로는 전역 객체의 속성을 직접 바꿨을 것이다. 결과가 맞으니 작업 자체는 문제없지만, 계획서에 절차로 옮길 때는 정확히 적어야 다음 사람이 재현한다.

계획서 1.5절에 이렇게 적으면 된다.

> 콘솔에서 `QUESTIONS`의 해당 문항 속성을 직접 바꾼 뒤 `validateData()`를 호출해 기대한 메시지가 나오는지 본다. 복구는 새로고침으로 한다. `const`로 선언한 전역이라 재할당은 안 되지만 속성 변경은 된다.

1단계 체크리스트의 `git diff` 항목은 남겨 둔다. 이 방식이면 자동으로 충족되고, 5단계 5.3절은 여전히 파일을 고치므로 그때 필요하다.

### 이탈 2 — `.claude/launch.json` 추가와 `.gitignore` 등재

**수용한다. 남겨도 된다.**

- 배포 산출물은 네 파일 그대로다. PRD 1.3절의 "빌드 과정 없이 정적 파일"이 유지된다
- PRD 4절의 "외부 의존성 없음"은 실행 시점의 의존성을 말한다. 개발 환경 설정 파일은 저촉되지 않는다
- `.gitignore`로 빠지므로 저장소 산출물에도 섞이지 않는다

사족 하나. `.gitignore`에 `.claude/`를 통째로 넣으면 나중에 프로젝트 단위 설정이나 스킬을 저장소에 공유하고 싶을 때 함께 막힌다. 지금 범위에서는 상관없고, 그때 가서 `.claude/launch.json`만 무시하도록 좁히면 된다.

또 하나. 작업 보고는 포트를 `8765`로, 검토 요청서는 `8000`으로 적었다. 재현 방법을 따라 하는 사람이 헷갈릴 수 있으니 한쪽으로 맞추면 좋다.
