# 커스텀 명령어 확인 — 세션 인계

- 받는 쪽: 이 저장소 폴더에서 새로 연 세션
- 작성: 노트 집필 세션 (작업 폴더가 달라 슬래시 명령어를 부를 수 없다)
- 목적: 강의 노트 5.2절에 적을 내용을 **직접 돌려서** 확정한다

**번호 안내** — 32번과 34번은 진행 중인 40문항 사실 검증 왕복에 예약되어 있다. 그래서 이 문서가 35번이다.

---

## 0. 왜 세션을 따로 여는가

슬래시 명령어는 **주 작업 폴더의 `.claude/commands/`만** 읽는다.

- 노트 집필 세션은 다른 폴더에서 열려 있어 이 저장소의 명령어가 보이지 않는다
- `/add-dir`로 이 폴더를 더해 보았으나 **명령어는 붙지 않았다.** 파일 접근 범위만 넓어진다
- 그래서 이 저장소 폴더에서 연 세션이 확인을 맡는다

## 1. 이미 확인된 것 (다시 하지 않아도 된다)

`/args-check 한국사 조선시대`를 돌려 얻은 결과다.

| 표기 | 들어온 값 |
|---|---|
| `$ARGUMENTS` | `한국사 조선시대` |
| `$0` | `한국사` |
| `$1` | `조선시대` |
| `$2` | 치환되지 않고 `$2` 글자 그대로 남음 |

- **첫 인수는 `$0`이다.** 교재는 `$1`을 첫 인수로 가르치는데 그것이 틀렸다
- **범위를 벗어난 자리표시자는 빈 값이 되지 않는다.** 글자 그대로 프롬프트에 들어간다. 문서에도 없던 내용이다
- 이 결과에 맞춰 `quiz-add.md`와 `quiz-daily.md`를 커밋 `2d1103c`에서 고쳤다

## 2. 확인할 것 — 순서대로

### 2.1 재시작 없이 반영되는가 (가장 먼저, 재시작하지 말 것)

`reload-check.md`는 **그 세션이 열린 뒤에** 만들어진 파일이다. 그래서 이 확인은 세션을 재시작하는 순간 못 하게 된다.

```
/reload-check
```

- 떴다 → 재시작 없이 반영된다. 최신 문서가 맞고 교재의 `/exit` 안내는 낡았다
- 안 떴다 → 한 번 재시작하고 다시 친다. 그때 뜨면 "재시작이 필요하다"가 확인된다. 그래도 안 뜨면 그 사실을 적는다

### 2.2 인수 없는 명령어

```
/quiz-stats
```

- 세는 일을 Node로 하는지, 손으로 세지 않는지 본다
- 결과 표가 PRD 3.6절 배분 규칙과 대조되는지 본다

### 2.3 인수 있는 명령어

```
/quiz-validate 지리
```

```
/quiz-validate
```

- 앞엣것은 `$ARGUMENTS`에 `지리`가 들어가 지리 10문항만 보는지
- 뒤엣것은 인수가 비었을 때 40문항 전체로 넘어가는지

### 2.4 체이닝

교재가 `&&`로 잇는 방식을 가르친다. 실제로 되는지 본다.

```
/quiz-stats && /quiz-validate 지리
```

- 둘 다 돌았는가, 앞엣것만 돌았는가, 아예 명령어로 안 잡혔는가
- 안 되면 **무엇이 안 되는지**를 적는다. 되게 만들려고 애쓰지 말 것. 안 된다는 사실이 노트에 들어갈 내용이다

## 3. 하지 말 것

- **`/quiz-add`와 `/quiz-daily`는 실행하지 않는다.** `questions.js`를 고치는 명령어인데, 지금 그 파일을 대상으로 40문항 사실 검증이 두 팀에서 진행 중이다. 검증이 끝나기 전에 문항이 늘면 두 팀의 결과와 파일이 어긋난다
- 커밋하지 않는다. 확인만 하고 결과를 넘긴다
- 명령어 파일을 고치지 않는다. 고칠 것이 보이면 적어서 넘긴다

아래 표를 채워서 노트 집필 세션에 넘긴다.

| 확인 항목 | 결과 | 비고 |

- 명령어 정의를 고쳐야 할 것이 보이면 파일 이름과 고칠 내용을 적는다
