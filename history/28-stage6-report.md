# 구현 6단계 완료 보고

- 대상: PRD 6절 6단계, 계획서 6단계 — 배포와 배포 후 확인
- 배포 주소: <https://logistex.github.io/Study03_QuizGame/>
- **R6가 이 단계에 있었다.** 파일명 대소문자와 상대 경로는 배포해야만 드러난다

## 1. 배포 구조

`gh-pages` 브랜치를 배포물로 두고 `main`은 소스와 문서만 담는다.

```
gh-pages/
├── index.html, style.css, script.js, questions.js   최신본
├── .nojekyll
├── stage1-final/   stage2/   stage3-final/   stage4-final/   stage5-final/
```

**계획서 6단계 범위 밖이다.** 계획서는 "정적 파일 넷을 그대로 올린다"만 적고 있고, 단계별 스냅숏은 노트의 미리보기(5.1.6.0)를 위해 더한 것이다. 5, 6단계 검토 요청에 함께 올린다.

정한 것 넷을 적어 둔다.

| 정한 것 | 왜 |
|---|---|
| `gh-pages` 브랜치를 따로 둔다 | `main`의 `docs/`를 쓰면 소스가 두 곳에 생기고, `main`에 스냅숏을 커밋하면 과거 코드 사본이 이력에 쌓인다. 태그가 이미 그 시점을 담고 있어 중복이다 |
| 스냅숏에 **파일 넷만** 넣는다 | `spec/`, `history/`, `archive/`까지 복사하면 같은 문서가 여섯 벌 생긴다 |
| 올리는 시점은 **`-final` 태그** | 5.1.6.0의 제목이 "완성된 모습"이므로 검토 반영 전 코드를 보여 주면 뜻이 어긋난다. 2단계만 `-final`이 없다. 검토를 3단계와 묶어 받아 단독 최종본이 존재하지 않는다 |
| `localStorage` 공유는 **안내 한 줄**로 갈음한다 | 여섯 주소가 같은 오리진이다. 저장 키에 단계를 붙이면 배포본 코드를 고치는 일이라 하지 않는다(26번 6절) |

갱신은 `git archive`로 한다. 태그 시점의 파일을 그대로 꺼내므로 워크트리를 만들 필요가 없다. 절차는 `CLAUDE.md`에 적었다.

## 2. 배포 후 확인

**로컬 확인을 완료 기준으로 삼지 않았다.** 아래는 전부 배포 URL에서 한 것이다.

### 2.1 자동으로 확인한 것

| 확인 | 결과 |
|---|---|
| 여섯 주소 응답 | 루트와 스냅숏 다섯 모두 200 |
| 자원 파일 | `style.css`, `script.js`, `questions.js` 모두 200 |
| Network 404 | **없음** |
| 콘솔 에러 | **없음** |
| 카테고리 도전 한 바퀴 | 결과 화면 도달, `순위표 1위 진입` |
| 전 범위 도전 한 바퀴 | 결과 화면 도달, `순위표 1위 진입` |
| 순위표 | 다섯 표가 그려지고 저장값에 `korean_history`와 `all`이 각각 한 건 |

절대 경로 참조가 없는 것도 올리기 전에 확인했다. `grep 'src="/\|href="/'`가 루트와 스냅숏 다섯 모두에서 아무것도 잡지 않았다. 하위 폴더에서도 자원이 뜨는 근거다(R6).

### 2.2 사람이 확인한 것

계획서 6단계 완료 기준을 사람이 배포 URL에서 밟아 **모두 문제없음**을 확인했다. Network 404 없음, 콘솔 에러 없음, 두 모드 한 바퀴, 새로고침 뒤 기록 유지, 사파리 한 바퀴, 두 탭 동시 저장까지다.

- **두 탭 동시 저장은 5단계에서 콘솔로만 확인했던 항목이다.** 배포 후 실제 탭 두 개로 닫혔다
- 사파리는 `file://`이 아니라 배포 URL이므로 `localStorage`가 정상 동작한다(PRD 4.1절)

## 3. 로컬과 배포본은 기록이 따로 쌓인다

`localhost:8010`과 `logistex.github.io`는 오리진이 다르다. 로컬에서 쌓은 순위는 배포본에 보이지 않는다. 확인할 때 헷갈리기 쉬운 자리라 적어 둔다.

## 4. 남은 것

- **5, 6단계 묶음 검토 요청** — 검토 측이 권한 순서다. 배포 후에만 드러나는 것이 있어 따로 보면 두 번 오간다
- **노트 5.1.6.0** — 단계별 실행 링크를 채운다. `localStorage`를 공유한다는 한 줄을 함께 넣는다
- **PRD 8절** — 2차 구현 예정 항목이 둘이다. 문제은행 확대, 선택지 개수 안내

## 5. 여섯 단계를 지나며

구현 자체는 여섯 단계로 끝났지만, 그중 **코드를 쓴 것은 1~4단계뿐이다.** 5단계는 점검만 했고 코드를 한 줄도 고치지 않았으며, 6단계는 올리고 확인한 것이 전부다.

- 검토를 네 번 받았다 — 1단계, 2와 3단계, 4단계, 그리고 4단계 회신에 대한 재검토
- 검토가 잡은 것 중 **화면으로는 정상인데 결과만 틀리는 것**이 여럿이었다. 초점 이중 이동, 저장 불가 상태의 순위표 안내, R1 판정 지표
- 규격은 구현 2~5단계 동안 **본문이 한 번 바뀌었다**(3.5절). 나머지는 검증 절차 수정이거나 8절 추가였다
