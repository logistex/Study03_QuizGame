## 1. 반영한 것

### 조치 1 — `id` 존재와 형식 검사 (필수)

중복 검사 앞에 존재 검사를 넣었다. 순서가 중요하다는 지적이 맞다.

```javascript
if (typeof q.id !== 'string' || q.id.trim() === '') {
  errors.push(label + ': id가 비어 있음');
} else if (seenIds.has(q.id)) {
  errors.push(label + ': id 중복');
} else {
  seenIds.add(q.id);
}
```

`id`를 지운 문항 두 개를 넣으면 이제 이렇게 나온다.

```
korean_history[0]: id가 비어 있음
korean_history[1]: id가 비어 있음
```

전에는 `korean_history[1]: id 중복` 하나만 나왔다. **누락을 중복으로 보고하던 것이 사라졌다.**

3단계 R2 체크리스트가 `find(o => o.id === q.id)`로 원본을 찾으므로, `id` 없는 문항이 1단계를 통과하면 그 검증이 예외로 죽는다는 지적이 정확했다. 검사 함수가 막아야 할 자리가 맞다.

### 조치 2 — 중복 판정을 `findIndex`로 (필수)

`find`의 반환값을 센티넬로 쓴 것이 제 실수였다. 중복 값이 `undefined`이면 `find`가 `undefined`를 돌려주는데 판정이 `!== undefined`라 참이 되지 않는다. **중복 검사가 반쪽으로 돌고 있었다.**

```javascript
// 값이 아니라 인덱스로 판정한다. find는 중복 값이 undefined일 때
// undefined를 돌려주어 "못 찾음"과 구별되지 않는다.
const duplicatedIndex = q.options.findIndex(function (option, index) {
  return q.options.indexOf(option) !== index;
});
if (duplicatedIndex !== -1) {
  errors.push(label + ": options에 중복된 선택지 '" + q.options[duplicatedIndex] + "'");
}
```

### 조치 3 — 선택지 원소 검사 (권고)

권고였지만 넣었다. 이것 하나로 빈틈 1번과 2번이 함께 막히고, 3번도 이중으로 걸린다.

```javascript
q.options.forEach(function (option, index) {
  if (typeof option !== 'string' || option.trim() === '') {
    errors.push(label + ': options[' + index + ']가 비어 있음');
  }
});
```

### 조치 4 — 계획서 1.5절 (권고)

메모리 검증 방식으로 고쳤다. 지적대로 절차를 정확히 적었다. `QUESTIONS`가 `const`라 재할당은 안 되지만 속성 변경은 된다는 점, 복구는 새로고침이라는 점을 명시하고, 실행할 코드 골격을 넣었다.

표도 열두 줄로 늘렸다. 새로 넣은 검사(선택지 원소, `id` 존재)와 원래 확인했던 V1, `question` 빈 값을 함께 담았다.

`git diff` 항목은 남겼다. 이 방식에서는 자동으로 충족되지만 5단계 5.3절은 파일을 직접 고치므로 그때 필요하다는 판단에 동의한다.

### 조치 6 — `sc_07` 선택지 (선택)

`림프구`를 `혈장`으로 바꿨다.

| | 선택지 |
|---|---|
| 전 | 백혈구, 혈소판, **림프구**, 적혈구 |
| 후 | 백혈구, 혈소판, **혈장**, 적혈구 |

혈액의 네 구성 요소가 되어 층위가 맞는다. 정답은 `적혈구`, 인덱스는 3 그대로라 과학 카테고리의 정답 분포 `[3,3,2,2]`도 바뀌지 않았다.

지적한 대로 `림프구`가 `백혈구`의 하위여서 둘이 나란히 있는 것이 어색했다. 혈소판이 엄밀히 세포가 아니라는 점은 그대로 남지만, 혈액 구성 요소를 묻는 문항의 오답으로는 자연스럽다.

## 2. 반영하지 않은 것

### 조치 5 — 문항 60자, 선택지 20자 검사 (선택)

**넣지 않았다.**

- PRD 3.6절의 작성 규칙이지만 **4.2절의 검사 아홉 항목 밖**이다
- 지금 넣으면 규격에 없는 검사가 늘어나는 쪽으로 흐른다. 검사 함수가 무엇을 보증하는지가 PRD와 어긋나기 시작한다
- 현재 데이터는 최장 33자, 11자로 여유가 크다

> **정정 (2026-08-15).** 위 근거는 성립하지 않는다. 2차 의견서 3절이 짚은 대로, 반영한 조치 1(`id` 존재)과 조치 3(선택지 원소)도 아홉 항목 밖이다. "밖이라서 안 넣는다"로는 조치 5만 가를 수 없다.
>
> 실제로 셋을 가르는 것은 **빠뜨릴 때 증상이 있는가**다. 조치 1은 3단계 R2 검증이 예외로 죽고, 조치 3은 빈 버튼과 "정답은 입니다."가 나온다. 조치 5는 증상이 없다. PRD 4.3절이 이미 "글이 길면 줄바꿈해 전부 보이게 한다"로 흡수하기 때문이다.
>
> 결론(넣지 않는다)은 그대로다. 근거만 바꾼다.

2차 문제 확대(PRD 8절) 때 PRD 4.2절에 항목을 추가하면서 함께 넣는 것이 맞다고 본다. 그때는 문항 수가 늘어 사람 눈으로 재기 어려워지므로 값어치도 커진다.

## 3. 정정 요청 — 경미 1건은 재현되지 않았다

의견서 2절 "경미 2건"의 첫 번째다.

> `QUESTIONS`에만 있고 `CATEGORIES`에 없는 키는 검사되지 않는다. 키를 잘못 적으면(`sciene`) 그 데이터는 조용히 죽는다.

**앞 문장은 맞고 뒤 문장은 틀리다.** 실제로 키를 `science`에서 `sciene`으로 바꿔 보면 이렇게 나온다.

```
science: QUESTIONS에 문제 배열이 없습니다
```

순회가 `CATEGORIES` 기준이라 **키를 잘못 적으면 원래 키가 사라지므로 반대 방향에서 잡힌다.** 조용히 죽는 경우는 `CATEGORIES`에 없는 키를 **추가로** 넣었을 때뿐이고, 그건 남는 데이터가 무시되는 무해한 상황이다.

결론(규격 위반이 아니므로 손대지 않는다)은 같으므로 조치는 없다. 다만 근거가 다르니 기록에 남긴다.

## 4. 검증 결과

빈틈 4건을 고치기 전후로 같은 값을 넣어 대조했다.

| 넣은 값 | 반영 전 | 반영 후 |
|---|---|---|
| `options[1] = ''` | 검출 못 함 | `kh_01: options[1]가 비어 있음` |
| `options[1] = 123` | 검출 못 함 | `kh_01: options[1]가 비어 있음` |
| `options[1] = options[2] = undefined` | 검출 못 함 | `options[1]가 비어 있음`, `options[2]가 비어 있음`, `options에 중복된 선택지 'undefined'` |
| `id` 삭제 (1문항) | 검출 못 함 | `korean_history[0]: id가 비어 있음` |
| `id` 삭제 (2문항) | `korean_history[1]: id 중복` (사실과 다름) | `korean_history[0]: id가 비어 있음`, `korean_history[1]: id가 비어 있음` |
| 선택지 중복 (정상 값) | `options에 중복된 선택지 '이성계'` | 같음 (회귀 없음) |

정상 데이터도 다시 확인했다.

sc_07 선택지: ["백혈구","혈소판","혈장","적혈구"] / 정답 적혈구
korean_history [3,2,3,2] {easy:4, medium:4, hard:2}

## 5. 문서 쪽 정정

의견서 3절이 짚은 작업 보고의 부정확한 서술을 고쳤다.

> "객체를 복제해 망가뜨렸다"고 적었는데, `validateData()`는 전역 `QUESTIONS`를 직접 읽으므로 복제본을 망가뜨렸다면 함수가 그것을 볼 수 없다.

지적이 맞다. 실제로 한 일은 복제한 문항을 **전역 `QUESTIONS`의 카테고리 배열에 넣은 것**이다. [06-stage1-report.md](06-stage1-report.md)에 정정 문단을 달았다. 기록을 지우지 않고 무엇이 틀렸는지 남기는 쪽을 택했다.
