# 3단계 작업 보고

- 범위: 계획서 3단계 — 문제 선정, 퀴즈 진행, 즉시 피드백
- 커밋: `741801f`
- 위험 구간 여섯 중 셋(R1, R2, R5)이 이 단계에 몰려 있다

## 산출물

| 파일 | 이 단계에서 한 일 |
|---|---|
| `script.js` | 셔플, 문제 선정, 진행, 채점, 피드백, 그만두기, 이탈 경고 |
| `style.css` | 퀴즈 화면, 선택지 버튼, 난이도 배지 셋, 정답과 오답 강조, 피드백 영역 |
| `index.html` | 손대지 않았다. 2단계 골격이 그대로 맞았다 |

정의한 함수는 열하나다.

| 함수 | 책임 |
|---|---|
| `shuffle(arr)` | Fisher-Yates로 섞은 새 배열을 돌려준다 |
| `prepareQuestion(q, category)` | 선택지를 섞고 `answer`를 새 자리로 갱신한 새 객체를 만든다 |
| `pickCategoryQuiz(categoryId)` | 해당 카테고리에서 열 문제를 뽑는다 |
| `pickAllQuiz()` | 카테고리를 섞어 3, 3, 2, 2를 뽑고 합친 결과를 다시 섞는다 |
| `startGame(mode, categoryId)` | 2단계 스텁을 채웠다. 상태 초기화 → 뽑기 → 화면 전환 → 렌더링 → 이탈 경고 |
| `renderQuestion()` | 상단 정보, 문제, 선택지를 그리고 문제 텍스트로 초점을 옮긴다 |
| `handleAnswer(choiceIndex)` | 채점, 버튼 잠금, 강조, 피드백 표시 |
| `goNext()` | 다음 문제로 넘어가거나 마지막이면 결과 화면으로 |
| `quitGame()` | 확인창을 띄우고 확인하면 기록 없이 시작 화면으로 |
| `enableUnloadGuard()` / `disableUnloadGuard()` | `beforeunload` 등록과 해제 |
| `finishGame()` | 스텁. 4단계에서 채운다 |

`state`에 `quiz`, `index`, `score`가 더해져 여섯 필드가 됐다.

## 위험 구간 확인

### R1 — 전 범위 도전의 배분과 최종 섞기

다섯 판을 새로 시작해 카테고리 순서를 뽑았다.

| 판 | 배분 | 최대 연속 |
|---|---|---|
| 1 | 3, 3, 2, 2 | 2 |
| 2 | 3, 3, 2, 2 | 3 |
| 3 | 3, 3, 2, 2 | 2 |
| 4 | 3, 3, 2, 2 | 1 |
| 5 | 3, 3, 2, 2 | 3 |

- 다섯 판 모두 합이 10이고 어느 카테고리가 3개인지 판마다 달라졌다
- **최종 섞기가 빠졌다면 매 판이 `예술 예술 예술 지리 지리 지리 …` 꼴로 뭉쳤을 것이다.** 판 4는 같은 카테고리가 연달아 나온 곳이 하나도 없다
- 연속 3이 나온 판이 둘 있으나 블록이 아니라 흩어진 자리에서 우연히 붙은 것이다

### R2 — `answer` 갱신과 원본 오염

```javascript
state.quiz.every(q => {
  const orig = Object.values(QUESTIONS).flat().find(o => o.id === q.id);
  return q.options[q.answer] === orig.options[orig.answer];
})
```

- 전 범위와 네 카테고리, 다섯 모드 모두 `true`
- 같은 카테고리로 세 판을 돌린 뒤 `QUESTIONS.korean_history[0].options`가 `이성계/이방원/정도전/왕건`으로 그대로였다
- 같은 문제를 스무 번 준비하니 선택지 배열이 열네 가지로 나왔다. 섞이기는 한다는 뜻이다

**화면 조작으로는 R2를 잡을 수 없다.** 강조와 피드백이 둘 다 같은 `answer`를 참조하므로 갱신을 빠뜨려도 화면 안에서는 앞뒤가 맞는다. 원본과 대조하는 것이 유일한 수단이다.

### R5 — `aria-live` 없음

`grep -nE 'aria-live|role="status"|role="alert"' index.html script.js`가 아무것도 출력하지 않는다. 피드백은 초점 이동으로만 전달한다.

## 계획과 다르게 한 것

없다.

두 가지를 적어 둔다.

**`preventDefault`가 생겼다.** 2단계 보고서에 "`script.js` 어디에도 `preventDefault`가 없다"고 적었는데, 그것은 카드 활성화가 막히지 않는다는 근거였다. 3단계에서 `beforeunload` 핸들러에 `preventDefault`가 들어갔다. 버튼과 무관한 자리이므로 2단계의 근거는 그대로 유효하다.

**미리보기 캐시가 또 났다.** 2단계와 같은 증상이라 포트를 8766에서 8767로 바꿔 해결했다. 3단계에서도 재발했으므로 다음 단계부터는 처음부터 새 포트로 시작하는 편이 낫겠다.

## 남은 것

**키보드로 선택지를 고르는 것은 확인하지 못했다.** 2단계와 같은 이유다. 브라우저 자동화 도구가 키 이벤트를 넣어도 기본 동작을 일으키지 않는다. 선택지가 진짜 `<button>`이고 `preventDefault`가 버튼 경로에 없으므로 근거는 성립하지만, 눌러 본 것은 아니다.

Tab으로 선택지에 간 뒤 Enter를 눌러 채점되는지 확인해 주면 닫힌다.
