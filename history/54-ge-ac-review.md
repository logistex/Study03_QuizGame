넷 다 이번 묶음보다 앞선 것이고 앞선 검증 라운드를 통과했다.
`ac_10`과 `ac_15`는 **새로 생긴 종류가 아니다.**

### 실제로 생기는 효과 하나

`ac_15`를 먼저 만나면 스트라빈스키가 「봄의 제전」 작곡가임을 알게 되고,

**난이도에 미치는 영향이지 규칙 위반이 아니다.** 답이 하나로 읽히는 것도, 오답 셋이 명백한 것도
그대로다. 앞의 넷도 같은 효과를 갖는다. **선 아래다.**

### 덧붙임 — 세는 눈에 걸리지 않는다

위 표를 뽑은 검사는 `ac_10`과 `ac_15`를 **못 잡았다.** `ac_10`은 "스트라빈스키",
`ac_15`는 "이고르 스트라빈스키"로 적어 문자열이 다르기 때문이다.
같은 카테고리 안에서 `ac_10`은 성만, `ac_11`과 `ac_15`는 성명 전체를 쓴다.
표기가 갈리는 것 자체는 답을 바꾸지 않아 선 아래이나, 6절에 적어 둔다.

## 6. 예술과 문화 — 권고 1건

### `ac_15` — 근거 주석이 데이터를 잘못 서술한다

**무엇이 어긋나는가.**

`questions.js`의 `ac_15`에 붙은 주석은 이렇다.

```
// 근거: 초연의 소란은 여러 출처가 전하나 원인은 갈린다. 문항은 소란이 있었던 사실만 쓴다.
```

그런데 해설은 원인을 적고 있다.

> 1913년 파리 샹젤리제 극장 초연 때 **파격적인 음악과 안무에** 객석이 크게 술렁였다.

53번 3절도 "소란이 있었다는 데까지만 쓰고 왜인지는 문항에 넣지 않았다"고 적었다.
`question`에는 정말 안 들어갔다. **`explanation`에는 들어갔다.**

**원인이 갈린다는 것은 대조로 확인했다.**

| 설명 | 출처 |
|---|---|
| 음악에 놀랐다 | 초연 목격자 진술 (위키백과 "The Rite of Spring") |
| 음악이 아니라 니진스키의 안무였다 | 타루스킨 (같은 문서) |
| 두 무리가 서로 공격하며 시작됐다 | 지휘자 몽퇴 (같은 문서) |
| 한 음도 듣기 전부터 방해할 작정인 무리가 있었다 | Classic FM |

해설의 "음악과 안무"는 앞의 둘을 덮고 뒤의 둘을 덮지 않는다.

**판정.** 계획서 1.8절 7번은 "자료가 갈리면 주류 학설을 따른다"고 했고,
해설이 고른 것은 주류다. **그래서 해설은 고치지 않아도 된다고 본다.**
어긋난 것은 **주석이 데이터를 잘못 서술하고 있다는 점**이다.

주석은 다음 세션이 같은 자리를 다시 파헤치지 않도록 두는 장치다.
지금 주석을 읽으면 "원인을 안 썼구나" 하고 넘어가는데 실제로는 썼다.
장치가 반대로 작동한다.

**권고 문구.** 문항은 건드리지 않고 주석만 바꾼다.

```
// 근거: 초연의 소란은 여러 출처가 전하나 원인은 갈린다(음악, 니진스키의 안무,
//       관객 무리 간 충돌, 사전에 방해할 작정이었던 무리). 해설은 주류 서술인
//       음악과 안무만 쓰고 나머지는 넣지 않았다.
```

이 문구에 새로 들어가는 사실은 없다. 위 표의 넷을 옮긴 것이고 넷 다 출처를 댔다.

**선에 대면.** 주석은 퀴즈를 푸는 사람이 보지 않으므로 엄밀히는 선 아래다.
그래도 올리는 까닭은 **주석과 데이터가 어긋난 것은 대조 기록이 어긋난 것**이고,
2차 판정 세션이 이 주석을 근거로 삼으면 확인하지 않은 것을 확인한 것으로 셀 수 있어서다.
채택 여부는 사람이 정한다.

## 8. 규격에 반영할 것

문항 지적과 섞지 않으려고 따로 모은다. 고칠 대상이 `questions.js`가 아니다.

**하나. 1.8절 7번의 주석 규칙에 "주석이 데이터와 맞는지"가 없다.**

규칙은 "자료가 갈리는 문항에는 판단 근거를 주석으로 남긴다"까지만 정한다.
주석이 실제 데이터를 맞게 서술하는지는 정하지 않는다. `ac_15`가 그 틈에 들어갔다 —
주석은 원인을 안 썼다고 적었고 해설은 썼다. 한 줄 더 두는 것을 제안한다.

> 주석이 서술하는 것과 `question`, `explanation`이 실제로 담은 것이 맞는지 확인한다.
> 어긋나면 다음 라운드가 주석을 믿고 그 자리를 안 본다.

**둘. 1.8절 8번의 좁히는 목록이 "정답이 다른 문항의 오답으로 쓰인 자리"를 안 뽑는다.**

지금 목록은 `question` 텍스트만 늘어놓는다. 그것으로는 `ac_10`과 `ac_15` 같은 자리가 안 보인다.
아래를 더하면 보인다. **다만 표기가 다르면(성만 vs 성명 전체) 이 검사도 못 잡는다.**
`ac_10`의 "스트라빈스키"와 `ac_15`의 "이고르 스트라빈스키"가 그 경우다.

```javascript
Object.entries(QUESTIONS).forEach(([cat, qs]) => {
  const ans = new Map(qs.map(q => [q.options[q.answer], q.id]));
  qs.forEach(q => q.options.forEach((o, i) => {
    if (i !== q.answer && ans.has(o)) console.log(cat + ': ' + o + ' — 정답 ' + ans.get(o) + ' / 오답 ' + q.id);
  }));
});
```

**뽑아만 주고 판정하지 않는다.** 5절에서 보았듯 이 자리는 위반이 아닌 것이 보통이다.

**셋. 인명 표기 기준이 없다.** 예술과 문화 안에서 `ac_10`은 성만, `ac_08`, `ac_11`, `ac_15`는
성명 전체를 쓴다. 답을 바꾸지 않아 문항 지적으로는 올리지 않았으나,
위 둘째 검사가 표기 차이로 새는 원인이기도 하다.

## 9. 남은 것

- **두 카테고리 모두 2차가 남았다.** 이 문서가 1차다. 계획서 1.8절이 두 번을 서로 다른
  세션이 하라고 정했고, 2차 세션도 문항을 쓴 세션이 아니어야 한다
- 이 세션은 `questions.js`를 **고치지 않았다.** 수정 여부는 사람이 정한다
