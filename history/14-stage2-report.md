# 2단계 작업 보고

- 범위: 계획서 2단계 — `index.html` 골격과 시작 화면
- 커밋: `2001225`

## 산출물

| 파일 | 이 단계에서 한 일 |
|---|---|
| `index.html` | 네 화면을 요소 id 계약대로 채웠다. 퀴즈, 결과, 순위표는 빈 껍데기에 `hidden` |
| `script.js` | `state` 선언, 화면 전환, 카드 렌더링, 이름 검증, 이벤트 바인딩 |
| `style.css` | 화면 전환 규칙, 시작 화면, 카드, 버튼, 초점 표시 |

정의한 함수는 다섯이다.

| 함수 | 책임 |
|---|---|
| `showScreen(screenId)` | 네 화면을 감추고 대상만 드러낸 뒤 그 화면의 제목으로 초점을 옮긴다 |
| `renderCategoryCards()` | `CATEGORIES`를 돌며 카드 버튼을 그린다. 문제 수는 `QUIZ_LENGTH`에서 조립한다 |
| `readPlayerName()` | 앞뒤 공백을 잘라 돌려준다. 비었거나 12자를 넘으면 안내를 띄우고 `null` |
| `clearNameError()` | 안내 문구를 지운다. 입력란의 `input` 이벤트에 건다 |
| `startGame(mode, categoryId)` | 스텁. 이름 검증을 통과하면 상태를 채우고 퀴즈 화면으로 넘긴다 |

`state`는 `playerName`, `mode`, `categoryId` 셋이다. 3단계에서 `quiz`, `index`, `score`가 더해진다. "이미 답했는가" 플래그는 두지 않았다(1단계 검토 합의).

## 완료 기준 확인

계획서의 다섯 절차를 순서대로 밟았다.

| # | 절차 | 결과 |
|---|---|---|
| 1 | 이름을 비운 채 한국사 카드 | 화면 그대로, `이름을 입력해 주세요.` |
| 2 | 한 글자 입력 | 문구 사라짐 |
| 3 | 13자 이름으로 카드 | 화면 그대로, `이름은 12자까지 입력할 수 있습니다.`, 입력란은 13자 그대로 |
| 4 | `홍길동`으로 카드 | 퀴즈 화면 전환, `state`가 `{홍길동, category, korean_history}` |
| 5 | 순위표 열기, 닫기 | 이름 없이도 열리고, 닫으면 입력란에 이름이 남음 |

3번이 핵심이다. **조용히 잘라 내지 않는다**는 규칙이 지켜지는지는 입력란의 글자 수로만 판정된다. 화면에는 안내 문구가 떴는지만 보이므로 절단 여부는 드러나지 않는다.

## 체크리스트 확인

| 항목 | 결과 |
|---|---|
| 키보드로 전체 조작 | 탭 순서가 입력란 → 카드 4 → 전 범위 → 순위표 보기 |
| Enter, Space로 카드 실행 | 통과 (아래 참고) |
| 초점 표시가 보임 | 카드에 Tab으로 이동한 화면을 찍어 확인 |
| 카드 라벨이 `QUIZ_LENGTH`에서 조립 | 라벨이 `QUIZ_LENGTH + '문제'`와 일치, 마크업에 `10문제` 없음 |
| `hidden`으로 화면 전환 | 감춘 화면에 속성이 붙고 그 안의 버튼이 탭 순서에서 빠짐(노출 0개) |
| 전환 뒤 초점이 제목에 | `ranking-title`, `start-title`, `quiz-title` 확인 |
| 입력란에 `maxlength` 없음 | 없음 |
| 카드가 `<button>` | `tagName`이 `BUTTON` |
| 카테고리가 `CATEGORIES`에서 | 마크업에 카테고리 이름 없음 |

### Enter, Space 확인은 사람이 했다

브라우저 자동화 도구가 키 이벤트를 넣기는 하는데 **브라우저 기본 동작을 일으키지 않는다.** 리스너를 붙여 확인하니 `keydown:Enter`는 도착하지만 클릭이 합성되지 않았다.

그래서 성립 근거만 먼저 확인했다. 카드가 진짜 `<button type="button">`이고, `script.js` 어디에도 `preventDefault`가 없고, Tab으로 초점이 가며 초점 표시가 보인다. 이 셋이면 Enter와 Space 활성화는 HTML 기본 동작이다.

**다만 근거상 그렇다는 것과 눌러 봤다는 것은 다르다.** 사람이 직접 눌러 `이름을 입력해 주세요.`가 뜨는 것을 확인했고, 그것으로 항목을 닫았다.

3단계 이후에도 키보드 활성화 항목은 같은 방식으로 나눈다. 초점 이동까지는 자동으로 확인하고 누르는 것만 사람이 한다.

## 계획과 다르게 한 것

없다.

다만 개발 중에 겪은 것을 적어 둔다. 브라우저가 `script.js`를 캐시해 새 코드가 실행되지 않았다. 강제 새로고침과 새 탭으로 풀리지 않아 미리보기 서버 포트를 8765에서 8766으로 바꿨다. `python3 -m http.server`가 캐시 지시를 보내지 않아 브라우저가 추정 캐싱을 한 것이다.

배포 후 사용자가 겪을 일과는 성격이 다르다. GitHub Pages는 캐시 헤더를 보낸다. 실제 헤더는 6단계에서 배포한 뒤 확인한다.

`.claude/launch.json`은 gitignore 대상이라 저장소 산출물에는 영향이 없다.

## 검토 시점

2단계만으로는 검토를 요청하지 않는다. 3단계 직후에 **2단계와 3단계를 함께** 본다(1단계 검토 2차 의견 6절 합의).

요소 id 계약과 접근성 기반(`hidden` 전환, 초점 이동, `<button>` 사용)이 2단계에 깔리고 3단계가 그 위에 얹힌다. 3단계 체크리스트의 초점 이동 항목은 2단계의 `tabindex="-1"`이 제대로 붙어 있어야 판정되므로 따로 볼 수 없다.
