## 2. 채택한 것

### 2.1 PRD를 2차 기준으로 정리했다 — 처방을 바꿨다

62번의 처방은 1차 서술에 "이건 1차의 것"이라는 표시를 붙이는 것이었다. **사람이 방향을 바꿔, 표시 대신 지우고 다시 쓰기로 했다.** PRD는 2차 개발을 위한 규격이어야 하고, 1차 기록은 [`archive/PRD-v5.md`](../../archive/PRD-v5.md)와 태그에 이미 보존되어 있다.

**지우기 전에 참조를 먼저 찾았다.** 그 검색이 하나를 막았다 — **6절을 통째로 지우면 뒤 절이 밀려 8절을 가리키는 자리가 전부 끊긴다.** 명령어 `quiz-add`와 `quiz-stats`가 PRD 8절을 가리킨다. 그래서 **번호는 두고 내용만 갈아끼웠다.**

```bash
grep -rn "6절\|5절\|4\.2절\|3\.1절" spec/ .claude/commands/ README.md
```

| 절 | 무엇을 했나 |
|---|---|
| 1.3 | 외부 라이브러리 — 미정인 것을 좁혔다(R1). 직접 조회는 3.8절이 이미 정했다 |
| 3.1 | 이름 입력 규칙을 지우고 로그인으로 다시 썼다 |

| 3.5 | 안내 문구를 서버 기준으로. 끊긴 참조(R3)가 함께 사라졌다 |
| 3.6 | 확인 수단 표의 "4.2절 검사 함수"를 "데이터 검사(4.2절)"로. 육안 검토 참조를 8.1절로 |

| 4.2 | 2차 기준으로 다시 썼다(F1) |

### 2.2 F1의 처방을 바꿨다

62번은 "나머지 항목의 시점은 계획서에서 정한다"로 뭉뚱그렸다. **검사 항목이 시점으로 갈리는데 그 갈림을 안 적으면 계획서가 2번을 통째로 삽입 시점에 둔다.**

| 무엇을 보나 | 언제 |
|---|---|
| 문항 하나 안에서 닫히는 것 | 넣는 시점 |
| `id`와 `question` 중복 | 넣는 시점. DB 제약이 더 강하다 |
| 카테고리 대응, 카테고리별 문제 수 | **넣는 시점에 판정할 수 없다.** 넣을 때가 아니라 지우거나 카테고리를 늘릴 때 어긋난다 |

**어디서 할지는 적지 않았다.** 근거가 없는 결정을 규격에 넣지 않기 위해서다. 이번 왕복이 짚은 것이 그것이고(57번 R1~R3), 그 기준을 내가 쓴 문장에 적용하지 않으면 기준이 서지 않는다.

### 2.3 `ge_14`는 고치지 않는다 — 61번 권고를 받지 않았다

61번이 해설의 "강원도에서 부산까지"를 빼라고 권했다. **받지 않은 까닭은 54번이 같은 자리를 이미 열어 보고 선 아래로 닫았고, 그 판정이 한 겹 깊기 때문이다.**

- 해설 문장 안에 "한반도 동부를"이 이미 있어 남한으로 좁히지 않는다
- 두 출처가 적은 함경남도 안변군과 북한 강원도 원산은 **같은 곳이다.** 1946년 개편으로 소속 도가 바뀌었다

61번은 54번을 안 읽고 도는 것이 규칙이라 이 확인을 거치지 않았고, "출처가 갈렸다"를 전제로 판정했다. **판정이 재현되지 않는다는 것을 이 자리가 다시 보였다.**

### 2.4 54번 8절의 셋을 계획서 1.8절에 넣었다

두 라운드가 다 놓치고 있던 것이다. 이미 끝난 단계의 검증 절차라 규격 동결에 걸리지 않는다.

| 무엇 | 어디 |
|---|---|
| 주석이 `question`, `explanation`과 맞는지 확인 | 1.8절 7번 |
| 한 문항의 정답이 다른 문항의 오답으로 쓰인 자리를 뽑는 검사 | 1.8절 8번 |
| 인명은 성만 떼어 한 번 더 대조 | 1.8절 8번 |

**인명 표기 기준은 규칙으로 세우지 않았다.** 성명 전체로 통일하려면 `questions.js`의 문항 여덟 개를 고쳐야 하는데, 얻는 것은 문자열 검사가 한 쌍을 더 잡는 것뿐이다. 데이터를 안 건드리고 검사의 단서로 흡수했다.

- 채택한 것 대부분이 문장 손질이고 새 결정을 넣지 않았다
- **다만 F1은 처방을 바꿨고 4.2절이 다시 쓰였다.** 그냥 넘기지 않는다
- `spec/IMPL-PLAN-2.md`를 쓰는 세션이 4.2절과 6절을 반드시 지난다. **그 세션이 두 자리를 확인하는 것을 계획서 착수 조건으로 둔다**
