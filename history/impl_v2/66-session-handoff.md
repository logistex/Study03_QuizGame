## 2. 이 세션이 한 일

### 2.1 2차 판정 둘을 대조하고 채택했다

[61번](../61-ge-ac-review-round2.md)과 [62번](62-prd-phase2-review-round2.md)이 "뒤에 대조한다"로 미뤄 둔 1차 대조를 먼저 했다. 결과는 [63번](63-round2-adoption.md)에 있다.

- **`ge_14`는 고치지 않았다.** 1차와 2차 판정이 갈렸고, 1차가 두 지명이 같은 곳임을 확인한 만큼 근거가 깊었다
- **62번의 여덟 건은 채택했다.** 다만 처방 방향을 바꿨다 — 1차 서술에 표시를 붙이는 대신 지우고 2차 기준으로 다시 썼다
- 54번 8절이 낸 검증 규칙 셋을 `spec/IMPL-PLAN.md` 1.8절에 넣었다. 두 라운드가 다 놓치고 있었다
- **3차 라운드는 열지 않는다.** 대신 계획서를 쓰는 세션이 PRD 4.2절과 6절을 확인하는 것을 착수 조건으로 두었다

### 2.2 PRD를 두 번 고쳤다

| 언제 | 무엇 | 보존 |
|---|---|---|
| 2차 검토 채택 | 절 열넷. 6절은 번호를 두고 내용만 갈아끼웠다 | — |
| 계획서 준비 중 | 절 열. 선행 결정 여섯이 규격에 없어서다 | [`archive/PRD-v6.md`](../../archive/PRD-v6.md) |

**6절을 통째로 지우면 뒤 절이 밀려 8절 참조가 전부 끊긴다.** 커스텀 명령어 둘이 PRD 8절을 가리키고 있었다. 지우기 전에 검색해 목록을 만든 것이 이것을 막았다.

### 2.3 계획서를 쓰기 전에 정할 것을 정했다

[65번](65-plan2-design-decisions.md)에 있다. 결정이 대화에만 남으면 프롬프트가 근거로 쓸 수 없다.

- 개발 단계 다섯, 검증은 단계마다 셋
- 로그인은 깃허브 하나, 역할은 사용자 테이블의 역할 열
- 화면 여덟 — 선생님 화면 셋(문항 관리, 성적 관리, 설정)
- 문항 관리에서 명령어 넷을 화면에서 부르고, 수정과 삭제를 둔다
- 카테고리당 상한 30, 연습 응시 모드, 대시보드는 라이브러리 없이 차트
- 배포는 브랜치에서 하고 단계 끝에 병합, 문서만 바뀐 커밋은 건너뛴다

**되돌린 결정이 하나 있다.** 선생님 아이디를 배포 환경 변수에 두려던 안이다. 값을 바꾸려면 배포 설정을 열고 다시 배포해야 해서 "선생님은 앱 화면에서만 작업한다"와 어긋났다. 까닭까지 65번에 남겼다.

## 3. 노트 5.3.7을 다시 나누기로 했다

**마지막 논의에서 정한 것이고 아직 반영하지 않았다.**

지금 5.3.7.4(완료 기준)와 7.5(검증 수단)는 계획서가 쓸 자리를 미리 적어 둔 모양이다. 정해야 하는 것은 개발 단계 구분까지다. 단계가 정해져야 프롬프트의 뼈대가 서고, 완료 기준과 검증 절차는 계획서가 채운다.

| 번호 | 제목 |
|---|---|
| 5.3.7.1 | 선행 결정 — 지금 넷에 개발 단계 구분을 더해 다섯 |
| 5.3.7.2 | 규격 공백 발견과 PRD 재개정 |
| 5.3.7.3 | 프롬프트 설계 |
| 5.3.7.4 | 프롬프트 실행과 결과 |
| 5.3.7.5 | 다른 세션의 검토와 반영 |

- 지금 7.3(단계 구분)은 7.1 안의 토글로 옮긴다
- 지금 7.4와 7.5의 내용은 버리지 않고 프롬프트 설계 목으로 옮긴다. "계획서에 이런 형식으로 쓰라"고 지정한 것이라 프롬프트에 들어간다

## 6. 주의할 것

- **노션에 한글을 유니코드로 적다 오타를 세 번 냈다.** 평문으로 넣고, 넣은 뒤 반드시 되읽는다

- **사용자가 노트를 직접 고친다.** 편집 전에 현재 문서를 다시 읽는다. 제가 알던 문구와 달라 편집이 실패한 적이 있다
- **규격을 고치면 그것을 가리키는 자리를 전부 찾는다.** 이번에도 3.5절에서 버튼을 빼자 같은 절의 표에 그 열이 남아 있었다
