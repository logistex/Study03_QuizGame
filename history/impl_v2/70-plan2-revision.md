### 3.4절을 어떻게 다시 썼나

| 무엇 | 전 | 후 |
|---|---|---|
| 정렬 | 점수 내림차순 하나. 동점은 안정 정렬로 | **키 둘** — 점수 내림차순, 동점이면 마친 때가 늦은 것이 위 |
| 보관 수 | 넘으면 가장 낮은 기록을 지운다 | **지우지 않는다.** 조회할 때 상위 N만 뽑는다 |
| 읽기 | 브라우저가 직접 | **순위표는 서버 함수.** 자기 응시 기록만 브라우저가 직접 |
| 함수 계약 | 읽기 → 삽입 → 정렬 → 자르기 → 쓰기 | 마치는 요청이 저장과 순위 판정을 함께. **자르기 단계가 없다** |
| 저장 구조 | `quizGameRankings` JSON | 순위표 테이블을 두지 않는다. 열은 3.10절 |

**남긴 것 넷** — 반환값 셋(정수 / `null` / `'unavailable'`), 인덱스를 행으로 찾기, 날짜에 `toISOString()`을 쓰지 않기, 같은 이름 기록을 합치지 않기.

**안정 정렬 문단을 지우지 않고 바꾼 까닭.** 1차가 "새 기록을 맨 앞에 넣고 점수로만 정렬"해 동점 순서를 얻었는데, 정렬이 DB로 가면 그 전제가 서지 않는다. 지우기만 하면 왜 키를 둘로 적는지가 남지 않는다.

**1차 저장 구조를 지웠다.** 1차 계획서가 그 자리를 다섯 곳에서 가리키는데, PRD 부록이 「1차 서술은 `archive/PRD-v5.md`에서 찾는다」로 이미 정해 둔 방식이다. [63번](63-round2-adoption.md)이 6절을 갈아끼울 때 쓴 것과 같다.
