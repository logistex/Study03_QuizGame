# 68번 — 2차 개발계획서 검토와 그 자리에서 정한 것

- [67번](67-plan2-write.md)이 낸 [`spec/IMPL-PLAN-2.md`](../../spec/IMPL-PLAN-2.md)를 다른 세션이 읽고 검토한 기록이다
- **이 문서가 계획서와 PRD를 고치는 근거다.** 고치는 세션은 여기 적힌 것만 근거로 쓴다
- 계획서를 쓴 세션과 검토한 세션이 다르다. 검토한 세션은 계획서 작성에 관여하지 않았다

## 1. 검토에서 본 것

### 1.1 큰 것 둘

| 무엇 | 왜 문제인가 |
|---|---|
| 순위표를 브라우저가 DB에서 직접 읽는다(결정 1, 3) | 순위표는 남의 이름과 점수를 보여 준다. 응시 기록에 전체 조회를 열면 "학생은 자기 기록만 조회한다"(PRD 3.8절)가 깨지고, 안 열면 순위표가 나오지 않는다 |
| 2단계 완료 기준이 5단계 산출물을 요구한다 | "학생 계정으로 선생님 화면을 열어도 그 요청이 거절된다"인데 그 요청(`api/authoring.js`, `api/users.js`)과 화면은 5단계에 생긴다. 2단계에는 확인할 대상이 없다 |

### 1.2 작은 것 다섯

- 답을 고른 뒤 **채점 요청이 실패하는 경로**가 없다. PRD 4.2절은 순위 저장 실패만 다루는데, 2차에서는 문항마다 서버를 지나므로 실패 자리가 새로 생긴다
- 결정 4의 GET이 **쓰기 가능 여부를 무엇으로 판정하는지**가 없다
- 결정 6이 공개 키를 서버 함수가 내려 준다고 했으나 **넷 중 어느 함수인지** 없다
- 결정 7이 "검사 열셋"이라 했으나 **PRD 4.2절 2번 표는 열둘**이다. 계획서가 3.6절의 "선택지 20자"를 더해 열셋으로 셌다
- PRD 4.2절 4번(저장 데이터 손상)이 `localStorage` 전제라 **2차에서 뜻이 없어졌다.** 계획서도 다루지 않고 67번의 "고칠 것"에도 없다

### 1.3 뒤에 더 나온 것 셋

- 1단계 테이블 목록이 사용자, 문항, 응시 세션, 생성 요청 넷인데 **응시 기록이 빠졌다.** 결정 3이 "순위는 응시 기록에서 뽑는다"고 하므로 만들 자리가 없다
- **만료 경고를 만드는 자리가 2단계**인데 2단계 작업 목록에 없다(아래 결정 3)
- **사용자 테이블 조회 정책이 역할에 따라 갈려야 한다.** 학생은 자기 줄만, 선생님은 전체가 보여야 설정 화면이 선다. 계획서에 그 조건이 없다

## 2. 정한 것 여덟

### 결정 A — 인증 클라이언트는 라이브러리를 쓰지 않는다

계획서 2단계가 열린 자리로 두었던 것을 닫는다. 인증 서비스의 깃허브 인증 경로로 보내고, 돌아온 주소에서 토큰을 직접 꺼내 쓴다.

- PRD 4절(CDN 금지, 빌드 없음)과 일관된다
- 로그인 흐름이 코드에 그대로 보여 수업에 쓰기 좋다
- 대가는 토큰 만료를 직접 다뤄야 한다는 것이고, 그 대가를 결정 C가 받는다

**이 자리가 닫혔으므로 2단계를 시작할 수 있다.**

### 결정 B — 토큰은 `sessionStorage`에 둔다

| 어디 | 새로고침 | 탭을 닫으면 |
|---|---|---|
| 변수 | 사라진다 | 사라진다 |
| **`sessionStorage`** | **남는다** | **사라진다** |
| `localStorage` | 남는다 | 남는다 |
| 쿠키 | 남는다 | 설정에 따른다 |

새로고침에 살아남아 실습이 끊기지 않고, 탭을 닫으면 지워져 실습실 공용 컴퓨터에 남지 않는다.

### 결정 C — 로그인 만료를 미리 알린다

토큰 안에 만료 시각이 있으므로 갱신을 만들지 않아도 남은 시간을 알 수 있다. **갱신은 만들지 않는다.**

**PRD 3.7절에 두 줄을 넣는다.**

```
로그인에는 수명이 있다. 만료되면 다시 로그인해야 하고, 만료가 가까우면 미리 알린다.
판을 시작하기 전에 남은 시간이 모자라면 먼저 다시 로그인하도록 안내한다.
```

**나머지는 계획서가 정한다.**

| 무엇 | 값 |
|---|---|
| 배너를 띄우는 때 | 남은 시간 5분 아래 |
| 판 시작 전 안내 | 남은 시간 10분 미만 |
| 401이 왔을 때 | 로그인 화면으로 보내고 문구를 낸다 |
| 문구 | `로그인이 만료되었습니다. 다시 로그인해 주세요.` |

**판 도중에 만료되면 그 판을 버린다.** 이어 하기는 PRD 7절이 제외했다. 그래서 판 시작 전 안내가 필요하다.

**PRD 7절이 제외한 게임 타이머와 다르다.** 화면에 시간을 세는 것이 들어가므로 계획서가 그 구분을 적는다.

### 결정 D — 순위표 조회는 서버 함수로 돌린다

1.1의 첫째를 이렇게 닫는다.

- 브라우저가 응시 기록을 직접 읽지 않는다. **행 수준 보안은 자기 기록만 열어 둔다**(PRD 3.8절)
- 순위표는 서버 함수가 상위 N만 뽑아 돌려준다
- 결정 1의 "브라우저가 직접 조회하는 것" 목록에서 순위표 조회가 빠진다

### 결정 E — 응시 세션 테이블을 두지 않는다. 응시 기록 행이 그 자리를 겸한다

계획서 결정 10을 대체한다. **결정 10은 PRD 3.10절이 정한 테이블 셋을 넷으로 늘린 자리이기도 했다.**

- 판을 시작하면 **응시 기록 행을 미리 만든다.** 섞인 순서, 문항별 응답, 마감 여부를 그 행에 담는다
- 답을 고를 때마다 그 행에 응답을 적고, 마칠 때 같은 행을 마감한다
- 연습 판과 "그만두기"로 끝난 판은 그 행을 지운다
- 문항별 응답이 그 행에 남으므로 대시보드의 "많이 틀린 문항"이 여기서 나온다

**PRD 3.10절 응시 기록에 열 셋을 더하면 규격 안에서 닫힌다** — 섞인 순서, 문항별 응답, 마감 여부.

**왜 순서를 서버가 알아야 하는가.** PRD 2.1절이 판마다 선택지를 섞고, PRD 3.8절이 정답을 브라우저에 내려보내지 않으며, PRD 1.4절이 브라우저는 고른 번호만 보내기로 했다. 정답이 없으니 브라우저가 섞을 수 없고, 서버가 섞으면 그 "3번"이 무엇인지 서버만 안다. 요청 사이에 서버는 기억하지 않으므로 저장하거나, 서명해 돌려받거나, 다시 계산해야 한다. **저장을 고르되 테이블을 새로 만들지 않는다.**

### 결정 F — 2단계 완료 기준을 2단계에서 확인할 수 있는 것으로 좁힌다

- **동작한다** — 깃허브로 로그인하면 시작 화면에 이름이 뜨고 게임을 시작할 수 있으며, 선생님 계정에만 선생님 화면 버튼이 보인다
- **거절한다** — 로그인하지 않으면 게임 시작이 막히고, **학생 계정으로 사용자 테이블을 조회하면 남의 줄이 보이지 않는다**

2단계에서 새로 생기는 권한 경계가 인증 식별자 열로 건 정책이므로 성격도 맞는다. **선생님 요청 거절은 5단계 거절 확인에 이미 있다.**

### 결정 G — 채점 요청이 실패하면 재시도하고, 그래도 안 되면 판을 버린다

- 답을 고른 뒤 응답이 오지 않으면 **재시도 버튼**을 낸다
- 재시도해도 실패하면 그 판을 버리고 시작 화면으로 보낸다
- 이어 하기는 PRD 7절이 제외했다

### 결정 H — 쓰기 상태는 순위표 조회 응답에 실어 보낸다

결정 4가 둔 별도 GET 호출을 두지 않는다. 순위표 조회가 서버 함수로 갔으므로(결정 D) **그 함수가 DB 연결과 쓰기 권한을 함께 확인해 상태를 같이 돌려준다.**

- 호출이 늘지 않는다
- PRD 3.5절의 세 상태 표는 그대로 선다
- **"한 판도 치지 않은 사용자에게도 가운데 상태를 낼 수 있다"**는 결정 4의 근거가 유지된다

## 3. PRD를 고칠 여섯 자리

| 절 | 무엇 |
|---|---|
| 1.4절 | `api/` 책임이 셋인데 3.8절의 역할 바꾸기가 빠져 **넷**이다 |
| 3.4절 | 1차 저장 계약이 그대로 남아 계획서 결정 3과 반대다. 순위를 응시 기록에서 뽑는 것으로 바꾼다 |
| 3.7절 | 로그인 수명과 만료 안내 **두 줄**을 넣는다(결정 C) |
| 3.10절 | 응시 기록에 **섞인 순서, 문항별 응답, 마감 여부** 세 열을 더한다(결정 E). 문항별 응답이 "많이 틀린 문항"의 자리다 |
| 4.2절 2번 | 검사 표에 **각 선택지 20자 이내**가 없다. 3.6절에는 있다 |
| 4.2절 4번 | 저장 데이터 손상이 `localStorage` 전제다. 2차 기준으로 다시 쓰거나 뜻이 없어졌음을 적는다 |

**고치기 전에 검색해 목록을 만든다.** 절 번호를 가리키는 자리가 `spec/`과 `.claude/commands/`에 있다.

## 4. 계획서를 고칠 자리

| 어디 | 무엇 |
|---|---|
| 결정 1 | 브라우저가 직접 조회하는 것에서 순위표를 뺀다(결정 D) |
| 결정 3 | 순위표 조회를 서버 함수로. `loadRankings` 계약을 그에 맞게 |
| 결정 4 | 별도 GET을 없애고 순위표 조회 응답에 상태를 싣는다(결정 H). 만료 문구를 문구 표에 더한다 |
| 결정 6 | 공개 키를 넷 중 어느 함수가 내려 주는지 정한다 |
| 결정 7 | "검사 열셋"을 PRD 표와 맞춘다 |
| 결정 10 | 응시 기록 겸용으로 다시 쓴다. 제목도 바꾼다(결정 E) |
| 함수 계약 | `api/submit.js`에서 GET을 빼고 순위표 조회를 넣는다. 응시 기록 행의 시작과 마감을 적는다 |
| 1단계 | 테이블 목록의 "응시 세션"을 "응시 기록"으로 |
| 2단계 | 열린 자리를 결정 A와 B로 채운다. 만료 경고를 작업 목록에 넣는다. 완료 기준을 결정 F로. **사용자 테이블 정책이 역할에 따라 갈리는 것**을 적는다 |
| 4단계 | 채점 실패 경로(결정 G). 응시 기록 행의 시작과 마감 |
| 5단계 | 설정 화면이 전체 사용자 목록을 보는 근거를 정책에 적는다 |

## 5. 고치지 않은 것

- **65번은 고치지 않는다.** 결정 E가 65번에 없는 것이지만 PRD 3.10절이 그 열을 담으면 규격이 근거가 된다. 근거 문서를 뒤늦게 고쳐 맞추지 않는다([56번](56-prd-phase2-revision.md)이 그렇게 하다 판단 흔적을 지웠다)
- **1차 계획서와 1차 배포본은 그대로 둔다**
