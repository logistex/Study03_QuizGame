# 64번 — 2차 PRD 요약

- 대상 — 커밋 `034099d`의 [`spec/PRD.md`](../../spec/PRD.md)
- 이 문서는 규격이 아니다. 정본은 `spec/PRD.md`이고 어긋나면 그쪽이 맞다
- 2차 개정이 닫힌 시점의 상태를 한 장으로 보이기 위한 것이다([63번](63-round2-adoption.md))

## 무엇을 만드는가

- 4지선다 상식 퀴즈 웹 앱, 수업용
- 로그인한 학생이 응시하고, 선생님이 문항과 성적을 관리한다
- 한 판은 10문제, 답을 고르면 즉시 정답 여부와 해설을 보여 준다
- 카테고리는 한국사, 과학, 지리, 예술과 문화 넷
- 카테고리 하나를 고르거나 전 범위 도전을 고른다. 전 범위는 3+3+2+2로 뽑는다

## 기술 구성

- 프레임워크 없이 HTML, CSS, 자바스크립트만 쓴다
- 인증과 저장은 Supabase, 서버 코드는 Vercel Functions(`api/` 폴더)
- 문항 생성은 서버 함수가 Anthropic API를 호출한다
- 배포는 Vercel, 배포 URL로 접속한다. `index.html`을 직접 열면 동작하지 않는다
- 외부 라이브러리 도입 여부는 `spec/IMPL-PLAN-2.md`에서 정한다

## 화면

- 시작, 퀴즈 진행, 결과, 순위표 넷에 로그인 화면이 앞에 붙는다
- 시작 화면은 로그인한 사용자만 진입한다. 이름을 따로 입력받지 않는다
- 선생님 화면을 몇 개로 나눌지는 미정이다

## 문항과 데이터

- 문항은 파일이 아니라 DB에 둔다. 정답을 브라우저에 내려보내지 않기 위해서다
- 테이블 셋 — 사용자, 문항, 응시 기록
- 비밀번호는 우리 테이블에 담지 않는다. 인증 서비스가 보관한다
- 문항 작성 규칙 여덟 가지는 1차의 것을 그대로 쓴다

## 권한

- 브라우저가 직접 읽는 것은 행 수준 보안이 거른다
- 정답 조회와 모든 쓰기는 서버 함수만 한다
- 채점도 서버가 한다. 브라우저에서 점수를 계산하면 조작이 가능하기 때문이다

## 문항 생성 절차

선생님이 화면에서 요청 → 서버가 역할 확인 → 생성 → 규칙과 검사 통과 → 선생님이 채택

- 채택 단계를 생략하지 않는다. 1차의 "클로드가 판정하고 사람이 채택"을 그대로 잇는다

## 검증

- 데이터 검사는 문항을 넣는 시점에 서버에서 한다
- 카테고리별 문제 수 검사는 넣는 시점에 판정할 수 없어 자리를 따로 정해야 한다
- 검사가 못 잡는 것(정답이 틀린 자리, 해설이 무관한 자리)은 클로드가 판정하고 사람이 채택한다

## 아직 정하지 않은 것 (8.3절)

- 2차 개발 단계를 몇 개로 나눌 것인가
- 화면이 몇 개가 되는가
- 대시보드를 어디까지 만들 것인가
- 문제은행 확대를 어디서 멈출 것인가
