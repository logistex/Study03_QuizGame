## 2. 구현 1단계를 닫은 방법

| 무엇 | 결과 |
|---|---|
| 완료 기준 두 줄 | 통과 |
| 검증 셋 | 통과 |
| 체크리스트 여덟 | 일곱 통과, 환경 변수 하나를 구현 2단계로 이월 |
| 태그 | `v2-stage1`을 두 저장소에 각각 붙임 |

**2차 구현의 태그 이름을 `v2-stageN` 꼴로 정했음.** 1차가 `stage1`~`stage6`을 규격 저장소에 붙였고, 2차는 코드가 실습 저장소에 있어 이름이 갈려야 노트에서 구분된다.

**`-final` 태그는 2차에 없다.** 1차에서 그것은 검토 반영 시점이었는데, 2차 계획서에 단계별 외부 세션 검토가 없다.

### 2.1 이월한 항목이 그날 풀렸다

75번이 "환경 변수 값을 확인할 수 없음"으로 닫았으나, 같은 날 로그인된 브라우저로 화면을 열어 확인했다. 목록에 이름과 환경과 추가일만 나오고 값 자리가 없다. **앞 두 부분은 화면으로 확인됐고 셋째만 구현 2단계로 남는다.**

## 7. 확인한 사실들

### 7.1 깃허브 OAuth 앱 등록 폼

옛 이름 `Authorization callback URL`이 아니라 **`Redirect URIs`**다. 실제 폼을 열어 확인했다.

| 칸 | 개발 용도 | 운영 용도 |
|---|---|---|
| Application name | `quiz-game-dev` | `quiz-game-prod` |
| Homepage URL | 대표 주소 | 왼쪽과 같음 |
| Application description | 비워 둠 | 비워 둠 |
| Redirect URI | `https://metcfkfnfioiuujuyhvu.supabase.co/auth/v1/callback` | `https://pfzoykdostevvvossgct.supabase.co/auth/v1/callback` |
| Allow wildcard matching | 끔 | 끔 |
| Enable Device Flow | 끔 | 끔 |
| Expire user access tokens | 끔 | 끔 |

**값이 갈리는 칸은 이름과 Redirect URI 둘뿐이다.**

### 7.2 Supabase 허용 목록

| 프로젝트 | 넣을 값 |
|---|---|
| 개발 용도 `metcf…` | `https://*-bdmp1.vercel.app/**` |
| 운영 용도 `pfzoy…` | `https://quiz-game-gamma-bay.vercel.app/**` |

**서로의 값을 넣지 않는다.** 프리뷰의 로그인은 개발 용도가, 대표 주소의 로그인은 운영 용도가 처리한다.

### 7.3 로그인 흐름

| 순서 | 누가 → 누구에게 | 무엇 | 등록해 둔 주소 |
|---|---|---|---|
| 1 | 학생 → 앱 | 로그인 버튼을 누름 | — |
| 2 | 앱 → Supabase | 「깃허브로 로그인 시작해 줘」. 돌아올 앱 주소를 함께 알림 | — |
| 3 | Supabase → 브라우저 | 깃허브 승인 주소로 이동시킴 | — |
| 4 | 학생 → 깃허브 | 승인 화면에서 허용을 누름 | — |
| 5 | 깃허브 → Supabase | 판정 결과인 승인 증서를 보냄 | 깃허브 `Redirect URI` |
| 6 | Supabase → 브라우저 | 증서와 `Client Secret`으로 토큰을 만들고, 토큰을 실어 브라우저를 앱 주소로 이동시킴 | Supabase `Redirect URLs` |
| 7 | 브라우저 → 앱 | 토큰을 실은 채 앱을 엶. 앱이 `sessionStorage`에 넣고 화면을 가름 | — |

**등록이 둘인 까닭이 여기 있다.** 4번과 6번이 서로 다른 자리다.

### 7.4 `Client Secret`은 넣은 뒤 지운다

깃허브가 만들 때 한 번만 보여 주고, Supabase도 저장 뒤 가린다. 어차피 다시 못 보므로 `.env`에 남길 까닭이 없다. 잃으면 깃허브에서 새로 발급받아 다시 넣는다.

**`Client ID`는 비밀값이 아니다.** 로그인할 때 주소에 실려 가므로 어차피 드러난다.

### 7.5 `Allow users without an email`은 켠다

앱이 메일을 쓰지 않고, 깃허브는 메일 비공개가 기본이라 끄면 계정에 따라 로그인이 막힌다. **한 계정의 문제를 앱 설정으로 푸는 것이 이 경우에는 맞다.** 처음에는 끄라고 했다가 신 교수 지적으로 뒤집었다.
