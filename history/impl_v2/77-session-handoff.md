## 2. 노트 C를 분리한 까닭과 방법

- C가 노션 편집 한도(서식 조각 100,000)를 1 넘겨 API 편집이 한 글자도 안 됐음
- 경계는 2차 구현 1단계(5.3.8.2)와 2단계(5.3.8.3) 사이. 끝난 기록은 C1에 동결하고, 작업 중인 부분만 C2로
- 기존 페이지를 C1으로 남겨 바깥 링크를 보존했고, C2가 새 페이지임
- 신 교수는 손질이 끝나면 다시 한 페이지로 합칠 계획임. 그래서 페이지 사이 링크의 정밀 정리는 하지 않고, 링크 전수 점검은 깨진 것만 잡는 수준으로 미뤄 둠(기억 파일 `note-split-link-audit-todo`)

## 5. d.1) 실행 기록

- d.1)은 실행 전에 전면 재설계했음: 열이 이미 1단계 스키마에 있음을 발견해(엉터리 프롬프트가 될 뻔), 제목과 프롬프트와 개념 설명을 다시 씀. 지금 노트가 정본임
- 실행: 정책 SQL(`db/users-policies.sql` + 마이그레이션 사본)을 대시보드 SQL 편집기로 두 프로젝트에 적용. `is_teacher` 함수로 정책 자기 참조(무한 반복)를 피함
- 확인 셋 통과: SQL 파일, `pg_policies` 2행씩, 공개 키 익명 조회 `200 []`
- CLI 마이그레이션 기록에는 안 남았음(편집기로 적용). `drop policy if exists`가 있어 나중에 `db push`가 다시 실행해도 무해함
- DB 비밀번호는 `.env`와 함께 사라진 상태였음. 대시보드 경로로 우회했으나, CLI 경로가 필요해지면 비밀번호 재설정이 필요함

## 7. 이 세션의 일 방식 (다음 세션에 그대로 적용할 것)

- 권고 전에 근거를 확인하고, 확인하지 않았으면 그 사실을 적음. 그런데 이것을 노트 문구에도 적용해야 함: 문구가 닿는 실물(스키마, 저장소, 화면)을 먼저 열어 봄. 이 세션은 그것을 늦게 해 신 교수가 문제를 먼저 잡는 일이 반복됐음
- 새 문구는 붉은색으로 넣고 신 교수가 검토 후 색을 걷는 방식. 표는 행 단위로 색을 걺
- 초안을 대화로 먼저 내고 승인 후 반영. 신 교수가 고친 것은 되짚어 보고하지 않음
- 프롬프트 실행은 신 교수가 입력해야 시작함(노트 캡처 장면). 앞질러 실행하지 않음
- 노션 편집 뒤 반드시 되읽음. 유니코드 코드값 오타(씁/쓸/씀, 누릀음)를 이 세션에서 세 번 냈고 되읽기로 잡았음
- 스크린샷이 문구와 어긋날 의심이 들면 내려받아 직접 봄
- aside 브라우저의 로그인 계정을 먼저 확인함. 이 세션 중 logistex와 haewoong007 사이를 오갔음
