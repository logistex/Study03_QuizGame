# 1단계 구현 검토 요약

## 개요

- 대상 커밋: `0a6097e`. 검토 파일 `questions.js`, `script.js`, `index.html`, `style.css`
- 방법: 40문항은 원본 지식으로 재대조, 검사 함수는 Node로 실행해 데이터를 망가뜨려 탐침
- 결과: 문제 데이터에 결함 없음. 지적은 전부 `script.js`를 향한다

## 문제 데이터 40문항

- `options[answer]`가 실제 정답인가 — 40문항 모두 맞다
- `explanation`이 정답의 근거를 설명하는가 — 40문항 모두 근거를 댄다. 문제를 되풀이하는 문장은 없다
- 해설의 연도, 수치, 인명 — 검증 가능한 23건을 대조했고 전부 맞다
- 정답이 둘로 읽히는 문항 — 없다
- 계측 재확인 — 문항 수, 난이도 배분, 정답 인덱스 분포, 길이 제한 모두 작업 보고와 일치

관찰 1건 (결함 아님)

- `sc_07` — 문항이 "세포"를 묻는데 오답에 `혈소판`이 있다. 혈소판은 세포가 아니라 세포 조각이다. 오답 `백혈구`와 `림프구`도 층위가 다르다. 림프구는 백혈구의 한 종류다
- 정답 판정에는 영향이 없다. 손대려면 `림프구`를 `혈장` 정도로 바꾸면 층위가 맞는다

## 검사 함수

- PRD 4.2절 아홉 항목을 모두 덮는다. 통과만 시키고 실질을 보지 않는 항목은 없다
- 실행으로 확인한 빈틈 4건

| 넣은 값 | 결과 |
|---|---|
| 선택지에 빈 문자열 | 검출 못 함 |
| 선택지가 숫자 | 검출 못 함 |
| 선택지 두 개가 `undefined` | 검출 못 함. 중복 검사 자체의 구멍이다. `find`가 중복 값 `undefined`를 돌려주는데 판정이 `!== undefined`라 참이 되지 않는다 |
| 한 문항의 `id` 삭제 | 검출 못 함 |
| 두 문항의 `id` 삭제 | `id 중복`으로 보고된다. 중복이 아니라 누락인데 `undefined`끼리 부딪힌 것이다 |

- `id` 누락이 가장 중요하다. 계획서 3단계 R2 검증이 `o.id === q.id`로 원본을 찾으므로, `id` 없는 문항이 섞이면 그 검증이 예외로 죽는다. 1단계를 통과한 데이터가 3단계를 깨뜨린다
- `script.js` 45줄이 `id` 없을 때 쓸 대체 라벨을 이미 만들어 두었다. 그 경우를 예상했으면서 오류로 보고하지는 않았다

잘된 부분

- 콘솔 출력이 `{id}: {위반 내용}`으로 일관되고 건수 요약 줄이 따로 있다
- `DIFFICULTY_LABELS`의 키로 난이도를 판정해 목록이 한 곳에만 있다
- 전역 상수 미정의를 먼저 보고 즉시 반환한다. 그 뒤 코드가 `undefined`를 순회하지 않는다

## 계획 이탈 2건

이탈 1 — 검사 함수 검증을 브라우저 메모리에서 수행: 수용. 계획서 1.5절을 이 방식으로 고칠 것을 권한다

- 검증의 목적은 함수가 망가진 상태를 보는 것뿐이다. 파일을 고치든 메모리를 고치든 함수가 보는 상태는 같다
- 오히려 낫다. 새로고침이 곧 복구라 복구 누락 위험이 구조적으로 없고, 임시 변경이 커밋에 섞일 수 없다
- 다만 "객체를 복제해 망가뜨렸다"는 서술은 부정확하다. `validateData()`는 전역을 직접 읽으므로 복제본을 망가뜨렸다면 함수가 볼 수 없다. 계획서에 옮길 때는 전역 속성을 바꾸고 새로고침으로 복구한다고 정확히 적어야 재현된다

이탈 2 — `.claude/launch.json` 추가와 `.gitignore` 등재: 수용. 남겨도 된다

- 배포 산출물은 네 파일 그대로이고, PRD 4절의 외부 의존성은 실행 시점을 말하므로 저촉되지 않는다
- 사족으로, `.claude/`를 통째로 무시하면 나중에 프로젝트 설정을 공유하고 싶을 때 함께 막힌다
